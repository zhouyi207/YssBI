Current implementation:
- graphProjection.ts uses one produce(next) for the graph root, node/port arrays,
  parameter-group/parameter arrays and their fixed DTO shells. Read-only old/next
  inputs drive comparisons; lazy draft access only writes fixed fields and array
  positions. Nodes match nodeId, ports match complete address, groups/parameters
  match key. A whole equal graph returns previous; a delta requiring no reference
  substitutions retains the incoming next root and its validation/freeze proofs.
- Simple position/display/capability/address/connection-capability/outcome records
  use shallow comparison. There is no full node/root generic recursive sharing or
  second node pass to repair positional port sharing.
- Truly opaque parameter value, literalOverride and protocolDefault are still
  shared outside draft traversal. Legal JSON keys do not become draft write paths.
- The existing helper ALSO remains for complex typed read leaves: basis,
  connections, diagnostics, portInstanceAdditions, typeState, resolvedSchema,
  parameter editor spec/valueType, plus the existing constant typed-shell's
  dataType/dataValue/tabular boundaries. This step does not claim these remaining
  recursive boundaries are eliminated or approved exceptions.
- The original candidate-level identity, duplicate node/port, graph-path,
  membership and endpoint checks remain. No protocol, sync baseline, revision
  trust shortcut, validation bypass, new owner or alternate production strategy
  was added.

Measurement scope:
- Exactly four 5000-node adoption groups were selected; sync parsing, initial-load
  and constants comparison tasks were filtered out.
- Delta uses the original ONE output port per node and continuously alternates
  one node's x coordinate via the existing Rust-owned set-path delta format.
  Input patch application, freezing and validation are in beforeEach, outside the
  measured installGraphSession call. beforeEach also captures prior state.
  afterEach now checks exact incoming projection identity, publication proof,
  changed-node position identity, an unaffected node, pins and graph-node order.
- Full-snapshot scenarios use TWO output ports per node so complete node/port
  reversal actually changes both orders. They are fresh equal content, one-node
  move, and reversal of all node/port arrays. Each sample restores the same
  installed base, receives a fresh frozen/validated snapshot outside the timer,
  then times installGraphSession only. Existing setup/afterEach verify content,
  old/new identities, no publication on equality, unchanged indexes and reorder.
- Both fixtures derive from editor-projection.json: one parameter group with one
  graphConstant editor, scalar Text valueType and a string UUID value; ports have
  null input and schema, exact scalar Binary typeState; connections, diagnostics,
  additions and resource-observation maps are empty. Constants are absent.
  This does not sample large opaque values, schemas, diagnostic dictionaries,
  graph connectivity or real project distributions.
- time=500 ms, iterations=30 minimum, warmupTime=100 ms were unchanged. Thus the
  fast delta case legitimately measured 181 iterations to meet its time budget.
- Registration order is delta, equal snapshot, move snapshot, reorder snapshot,
  all in one process. Fixtures and timed bodies were unchanged; only delta's
  outside-timer assertions/captured previous state were strengthened this batch.
  Hooks can still affect retained memory or later GC even though they are not timed.
- Root coordinated an exclusive CPU window: no other agent tests, builds,
  typechecks or lint ran concurrently. OS/background activity was not instrumented.
  All module-level fixtures remain part of this process's memory context.
