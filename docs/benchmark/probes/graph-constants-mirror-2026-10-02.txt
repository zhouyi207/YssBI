Graph constants-only read mirror: existing full-snapshot adoption
Date: 2026-10-02, local Asia/Shanghai
Record scope: one uninstrumented fresh process, three 5000-node adoption scenarios.
Command:
pnpm bench:graph --testNamePattern='^5000 nodes: existing graph .* snapshot adoption$'

Measured change:
- GraphEditorState no longer retains the complete GraphDocumentDto or recursively
  shares its nodes, parameters, connections, port_bindings and input_states.
- The existing ResourceStore session retains the constants actually consumed by
  frontend constant editing/selection. Constant contents still undergo sharing
  and are not accepted as equal based on revision or semanticInputHash.
- Node membership and node type consumers reuse the existing graph entity index.
  Rust projection/mapper.rs constructs every document node in projection.nodes;
  the frontend does not create another document-node index.
- Graph node/port identity sharing from the preceding retained implementation
  is unchanged. Old objects remain immutable; shared delta input identities,
  fresh equal no-publication and atomic rejection behavior remain required.
- Complete wire documents still pass existing IPC parsing/freezing. The transport
  baseline may retain the document. This change does not remove its sync cost.

Benchmark comparability:
- Same synthetic 5000 nodes, two ports per node, equal / one-node move / all node
  and port reorder fixtures. Constants are EMPTY in these samples.
- Same time=500, iterations=30, warmupTime=100 settings and exact three-group filter.
- The timed callback is unchanged: installGraphSession(graphPath, received.data).
- Receive, JSON materialization, freezing, validation and input preparation occur
  outside adoption timing. Each sample restores the same installed base state.
- Only an offline identity-check dependency changed in benchmark source:
  setup captures received.data.document as baseDocument, and the existing fresh
  document assertion compares against it instead of the removed session.document.
  The previous Store already retained that same base document object.
- Fixtures and scenario validation are unchanged; no checks were relaxed, no
  helper instrumentation was installed, and no prior strategy was restored.
- Other agents paused tests, Cargo and typechecking during this process.
- Pre/post hashes of six directly relevant files below match. HEAD is dirty and
  therefore does not alone identify the measured implementation.

Historical comparison and limits:
- Previous retained node-wise sharing, with full document mirror, was recorded in
  graph-existing-snapshot-aligned-2026-10-02.txt, section "Final retained implementation":
    equal 89.6332 ms +/-3.73%, move 101.94 ms +/-3.60%,
    reorder 223.81 ms +/-2.75%; 30 samples each; same three-group filter.
- The observed means here are 45.84%, 46.13%, 46.36% lower, respectively.
  They are sequential independent processes on the same machine and synthetic
  fixtures, not a randomized paired comparison or isolated attribution of the
  entire difference to one function. GC and process/system history can affect them.
- No new old-strategy control was executed. The prior old positional strategy is
  not an equal-reference-behavior comparator and fails the added reorder identity
  regression; it is not the default Immer baseline.
- This measurement does not justify a rule exception for retained generic
  recursion. Constants/projection sharing still needs its remaining audit.
- Empty constants do not establish costs for large/tabular constants. No claim
  about sync/combined latency, Rust Resolve, real Tauri IPC, UI/DOM/frame rate,
  peak memory or end-to-end desktop speed is made.
