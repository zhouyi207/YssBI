Semantic limitation and decision:
The reference DOES NOT cover all legal JSON. Rust DataValue::Object is a BTreeMap
with unrestricted string keys (yss-data-contract/src/data_value.rs), and the
frontend literal validator permits own "__proto__" keys. Tabular column names
likewise have no such exclusion. Current Immer 11.1.18 proxy.set checks a prototype
setter before handling an own property, so restoring an equal object-valued
"__proto__" branch throws Object.setPrototypeOf. This was observed in the real
temporary candidate and reproduced with a minimal public-API command.

The candidate was removed from production. graphProjection.ts constants uses the
original shareProjection again. The candidate body moved to test/benchmark support,
with an explicitly restricted reference name. There is no production selector,
fallback, alternate owner, new input restriction, or retained unused production
module. The production legal-key regression is green; no test was added merely
to assert framework failure.

The measured ordinary-key fixtures satisfy the asserted equality/reference
behavior for both implementations, but this does not prove full-domain equivalence.
These timings therefore do not approve this candidate, do not grant a constants
rule exception, and do not exempt the remaining generic projection reconciliation.
They also do not prove that every possible future Immer design is impossible.
