## 第十类：文件系统与文件监听（FS），共 1 个

四个旧 crate 已合并为 `yss-filesystem`，只保留文件系统语义，所有依赖 scope 均没有 YssBI 内部 crate。

| 模块 | 职责 |
| --- | --- |
| root / identity | 明确的目录路径、原生 RootIdentity、安全相对路径及独立 TransactionId |
| coordinator / transaction / recovery | 文件访问协调、暂存、提交、回滚和恢复状态 |
| change | FileChange 与 RescanRequired 等通用文件变化事实 |
| watcher / watcher::notify | 监听接口、会话替换、epoch 隔离、关闭排空和 notify 适配 |

Project 负责项目入口解释、目录布局、文档校验、ProjectIndexInvalidation 和 ProjectOperationError。Application 传入项目路径过滤器，并在项目切换时管理监听。FS 默认允许任意文件字节和文件类型，不默认校验 JSON，也不识别 metadata.yssbi。

`yss-project-layout`、`yss-resource-naming` 继续归项目规则；CSV/Parquet 格式与数据集快照继续归数据模块。atomicwrites 和 dunce 按其实际调用方声明，不因此成为 FS 的内部依赖。

当前 API 与实现边界见 [yss-filesystem](../../src-tauri/crates/yss-filesystem/README.md)。

## Node 与 Graph 的边界

内部正式依赖分为 10 类，其中 Node 为 3 个，Graph 为 11 个。

- `yss-node-protocol` 声明节点类型、端口、参数、类型约束和执行语义。
- `yss-node-registry` 负责节点、类型和提供者的注册、校验及指纹。
- `yss-node-catalog` 负责内置节点定义、分类、创建描述和节点目录本地化。

Node 描述 OLS 等节点类型的能力和接口，不依赖任何 Graph crate。图中的 DocumentNode、位置、连线属于图文档；连接后解析的类型、Schema、血缘和诊断仍由 GraphSemanticSnapshot 统一管理。`yss-graph-type-mapping` 留在 Graph。

编译诊断定义和模板由 `yss-graph-compiler-diagnostics` 拥有，Graph Runtime 初始化时独立校验定义，前端 Graph 通过生成模板统一渲染。节点目录已移除编译诊断装配及其 Graph 依赖，只提供节点元数据文本查询。

Application 的 11 个 Graph 直接依赖不包含 `yss-graph-compiler-diagnostics`；后者由 Graph Runtime 等 Graph crate 使用。全 workspace 的 Graph 类别还包含这一诊断 crate，因此不能将直接依赖数量作为全 workspace 数量。
日志平台接入由入口注册的 `tauri-plugin-tracing` 负责：前后端运行观测统一进入结构化日志，写入 SQLite，并通过日志 Channel、历史分页及统计查询交付。业务代码使用 tracing 或已有前端日志服务；Graph Problems、模型诊断、结果和程序输出保持各自业务事实源。边界见 [Runtime Signals](../architecture/RUNTIME_SIGNALS.md)。
