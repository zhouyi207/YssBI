## 整体架构

YssBI 采用基于 Tauri 的桌面前后端分离架构，先从前端、通信和后端三个部分进行梳理。Tauri 提供桌面应用运行环境，React 在 WebView 中呈现界面，Rust 在后端处理业务，两者通过 IPC 交换请求、结果和通知。

macOS、Windows、Linux 是同等目标平台。基础库选型应覆盖三个平台，平台差异收敛在对应适配实现中；项目格式、业务规则和通信契约保持一致。库的跨平台支持是选型前提，实际支持情况仍需通过各平台的构建与运行验证。

```text
前端 React：展示与交互
    ↕
通信 Tauri IPC：请求、响应、通知与数据流
    ↕
后端 Rust：业务处理、计算与数据持久化
```

### 前端：React

前端负责将业务数据组织成用户能够查看和操作的界面，并把用户操作转换成明确的业务请求。

- **界面展示**：呈现工作台、图编辑器、数据表格和计算结果等内容。
- **用户交互**：处理点击、选择、拖动、输入以及打开、保存、执行等操作入口。
- **前端状态**：管理界面布局、选择状态、加载状态和未保存的编辑草稿，保存后端数据的显示投影。
- **反馈呈现**：根据响应和通知更新界面，将稳定错误码转换为本地化提示。

前端按应用与工作台、项目与资源交互、图编辑与运行交互、数据浏览与编辑、图表编辑与展示、Assistant、插件交互与接入、运行诊断与反馈、通信适配、客户端设置与通用支撑十个子系统展开，再分别梳理内部结构、状态归属和协作关系。

页面布局的目标约定是使用 **JSON 驱动模板**：JSON 声明页面分区、组件组合和默认布局，由页面宿主解析并渲染。工作台运行中的布局仍由根 Dockview 管理，模板、业务展示文档和持久化布局快照分别承担各自职责。该约定不表示所有页面已完成模板接入，具体边界在[前端草稿](frontend.md)中展开。

前端可以持有数据，但应区分数据的用途：界面状态由前端管理，未保存草稿保留用户尚未提交的编辑，已提交业务数据则以后端为准。前端不另建一套已提交项目模型，也不承担数据库查询和统计计算。

前端通过通信接口请求后端能力；收到响应后，校验数据及当前请求身份，再更新对应界面。保存成功后采用后端返回的状态，保存失败时保留未保存草稿。

### 通信：Tauri IPC

通信部分负责连接 React 与 Rust，约定如何表达请求、传递结果和交付通知。它承载前后端之间的交互契约，包括接口名称、参数、返回数据、错误结构和流的生命周期。

| 方式         | 职责                           | 典型用途                                       |
| ------------ | ------------------------------ | ---------------------------------------------- |
| Command      | 前端发起请求，后端返回处理结果 | 查询数据、提交编辑、保存、编译、启动或取消任务 |
| Event System | 交付低频变化通知               | 通知资源已提交或项目发生变化                   |
| Channel      | 持续交付有序消息               | 任务进度、执行事件和诊断流                     |

Command 调用由前端 `src/services/` 封装，统一经过 `invokeCommand`；后端由 `yss-api` 定义和注册对应命令。命令负责解析参数、转换传输数据和调用业务用例，具体业务处理交给 Rust 应用层或领域模块。

Event 用于通知变化，不作为完整业务状态的存储。前端需要时通过查询获取后端当前状态。Channel 由前端创建并通过 Command 传给后端，后端通过它发送后续消息；订阅结束或所属界面关闭时，需要按对应接口约定清理订阅。

前后端通过明确的数据结构（DTO）交换信息。Command 失败统一返回 `{ code, details, incidentId }`，由前端解释并呈现。通信部分负责这些数据的传递和映射，不拥有业务规则或已提交状态。大表数据优先在后端查询、筛选和分页，再返回界面需要的部分。

### 后端：Rust

后端负责执行可信的业务操作，管理已提交状态，并保证数据、计算和持久化之间的一致性。

- **业务编排**：接收通信层转交的请求，协调项目、图、数据库和执行等能力，检查操作所属的项目与会话是否仍然有效。
- **领域逻辑**：校验业务规则，解析图的类型和依赖，处理编译、执行与科学计算。
- **状态管理**：管理已提交项目、资源版本、编译产物和执行结果，为前端提供可查询的状态与投影。
- **数据访问与持久化**：负责项目文件、数据集目录和表数据的读写，以及数据查询、导入导出和提交事务。

后端将处理结果通过通信接口返回；需要持续反馈的任务通过事件或 Channel 交付相应消息。后端不直接操作 React 组件，也不决定界面布局。

数据访问与持久化作为后端内部职责，不增加与前端、通信、后端并列的第四部分。Rust 后端包含应用与会话、项目与资源、图分析与执行、数据、科学计算、Assistant 和插件七个业务子系统，以及通信适配、基础支撑两个技术子系统。基础支撑负责启动组装、日志诊断和通用技术操作，项目专属的文件系统与监听能力仍归项目与资源管理。

后端模块化遵循“每个 crate 只归属一个子系统，允许跨子系统依赖与协作”。归属按实际职责确定；共享接口的调用方不改变其归属，尚未符合边界的实现单独记录并逐步调整。

整体架构中的通信部分说明前后端完整交互链路；后端通信适配子系统说明 `yss-api` 的内部组织，承接同一链路的 Rust 一侧。
