## 已确认的产品约定

1. 参数可以在节点未连接时配置，也可以随节点创建请求提交；可变 Pin 的初始数量也属于创建配置，例如回归节点 Y 固定为 1 个，X 在创建时指定为 N 个。
2. 依据有效输入结构增强控件与校验；连接存在本身不表示列结构已知。
3. 已知列可提前显示，端口值和数据预览仍来自实际执行结果。
4. 未知列与确定不存在的列分别处理；待验证不等于参数非法，也不等于可以直接执行。
5. 连接、断开、更换输入及控件切换不清空参数，不自动替换成第一项，不将旧列选项伪装成当前输入。
6. 手动分析支持算一步看一步；AI 同时支持批量建图和执行后检查。
7. 保留明确的数据依赖、Rust 权威状态和查询优化。用户明确保留的执行步骤形成稳定结果，批量执行内部不要求每个节点都完整物化。

本计划不引入 Python 代码单元或全局可变变量环境，不重做画布布局。Graph 继续表达数据依赖，控制流与副作用遵循既有 Workflow 边界。项目尚未发布，接口变更直接更新全部消费者，不增加旧格式迁移或兼容字段。

## 核心数据流与依赖关系

```text
Protocol 与冻结 Registry
    ├─ 创建前参数定义 → GUI 表单与 AI 目录查询
    └─ 参数自身校验

GUI 创建请求 / AI 批量编辑
    → Application 捕获图版本与资源身份
    → Graph Editor 合并初始参数并构造候选补丁
    → Graph Analysis 解析输入上下文与诊断
    → Project 原子提交文档与历史
    → Editor Projection / Harness 回执

连接或输入事实变化
    → 同一 Graph Analysis 重新解析
    → 更新候选选项与诊断，保留文档参数

P5 之后的显式运行
    → 捕获执行范围与输入结果版本
    → Execution 准备并执行匹配计划
    → ResultStore 发布稳定结果与来源依据
    → 用户或 AI 检查结果，继续下一步
```

Node 声明层不依赖 Graph、Application 或 UI。Graph Analysis 消费文档、协议和捕获的输入事实；投影与 AI 检查从这些事实派生。创建前表单尚未提交的输入属于局部交互状态，不能成为第二份 GraphDocument。

## 参数配置契约

### 基础值与上下文约束

同一个参数只保留一种规范存储形式。列名保持字符串，列列表保持有序字符串数组，筛选条件保持现有结构化谓词；控件从输入框变为选择器不改变数据格式。列名遵循现有 `TabularColumnName` 规则，保留有意义的首尾空格，不用逗号拼接字符串替代数组。

| 输入上下文                      | 可用编辑形式                               | 语义处理                                       |
| ------------------------------- | ------------------------------------------ | ---------------------------------------------- |
| 未连接                          | 文本、按项录入的列表、结构化筛选表单       | 校验值本身；列存在性与列类型待验证             |
| 已连接但 Schema 待定或 Deferred | 同一基础表单，可提示待验证原因             | 不把未发现列判成不存在，不使用旧输入的候选项   |
| Schema 已知                     | Select、多选或搜索选择，固定枚举维持原控件 | 后端检查列存在性、列语义、操作符和字面量适用性 |
| Schema 已知且字段集合为空       | 明确展示没有可选列，保留原值及诊断         | 空集合是已知事实，不能回退成未知结构           |
| Schema 冲突或资源不可用         | 参数仍可修正，同时展示输入问题             | 保留真实诊断，不能将错误降级为普通未知         |
| 断开或更换输入                  | 按新上下文选择控件，保留已填写值           | 重新校验；旧选择不自动删除或替换               |

候选项只包含当前可选值。已保存但不匹配的值单独显示为无效项，允许删除或修改；不能因它不在候选项中而从表单消失。多输入节点按参数声明的输入来源约束，如左右连接键分别读取左右 Schema。

### 校验时机

- 参数自身校验：未知参数名、错误值类型、固定枚举非法值、违反固有数值范围、无法解析的表达式或谓词，在提交边界拒绝。复用 Protocol 与 Registry 校验，不另写 GUI 或 AI 的权威规则。
- 编辑完整性：必填字段尚未填写、数据输入未连接时，可保存为未完成节点并继续逐字段配置。实际执行要求本次范围的必要参数与输入齐备。
- 上下文校验：输入结构已知后，缺失列和不适用的列类型形成定位到参数的诊断。允许保留这些意图并修正，受影响计算不能执行；此行为不放宽连接方向、端口容量或明确不兼容类型的结构校验。
- 未知上下文：在投影中说明待验证原因；不能生成虚假的“列不存在”，也不能制造 Ready 证明。P1 至 P4 仍遵循当前执行准入，P5 才改造局部准入。
- 条件字段：复用 `Parameters::merge_values` 的显式条件切换与不适用值清理。连接变化不属于同节点条件参数切换，不借此清空列引用。

有效、待验证、不匹配等展示状态从当前 Schema 与诊断派生。参数编辑器的单一 `editor` 契约继续承载编辑能力；未知候选集与已知空候选集必须可区分，不再用“不可用”同时表达未知结构和禁止编辑。

## 携带参数创建与 AI 契约

### 创建请求

扩展现有 `CreateNode` 增加 `parameters` 与 `portCounts`。参数值使用现有 `ParameterValues` 及对应 wire 表达；`portCounts` 按协议端口模板 key 指定初始实例总数。所有 GUI、Harness、测试和内部调用方更新到当前契约；快速创建提交空集合并沿用协议默认数量，创建前配置提交用户显式填写的字段与数量。

Harness 的携带参数创建操作示例：

```json
{
  "type": "create_node",
  "payload": {
    "clientId": "summary",
    "nodeTypeId": "yssbi.dataframe.groupby",
    "resourcePath": null,
    "x": 320,
    "y": 160,
    "userLabel": "按行业汇总",
    "parameters": {
      "keys": ["industry"],
      "mean": ["sales"]
    },
    "portCounts": {}
  }
}
```

参数属于节点实例的创建请求，不塞进权威目录描述作为可伪造的节点定义。创建与后续 `SetParameters` 共用参数处理规则：显式值覆盖协议默认值，未填写的默认值不批量写入文档，null 沿用清除显式值的含义。

资源绑定描述继续由后端核对资源身份和版本；若初始参数试图改变描述已绑定的资源，拒绝整个创建，不允许通过参数覆盖绕过资源校验。managed 节点维持现有专用创建和编辑边界。

创建时先形成完整候选参数，再生成参数驱动的端口及类型事实。创建并连接时，对该候选节点进行匹配，避免按默认空参数选择端口。基础参数错误使创建整体失败；未连接或上下文不匹配产生可继续编辑的节点与诊断。

### 创建时配置 Pin 数量

回归节点可一次创建为 `Y × 1、X × N`，无须创建后重复点击 Add Pin。`portCounts` 表达最终初始数量，
不是在默认数量上追加的次数；未指定的模板遵循协议初始数量。

- 固定 Pin 由协议生成，在创建界面显示固定数量，不接受数量覆盖。
- 用户可增减的 Pin 显示数量输入，创建前查询提供模板 key、方向、最小值、最大值与关联成员组。
  数量必须是协议范围内的整数；仅当协议允许零个时可填 0。
- 同组端口共同扩展，复用现有 member group 规则；相互矛盾的数量配置整体拒绝，不生成残缺成员组。
- 按 DataFrame 列或函数签名派生的 Pin 继续由语义解析或资源契约决定，不能通过数量字段伪造列和成员身份。
- 参数、初始 Pin、可选自动连线纳入同一个创建补丁和一次撤销；数量错误、资源过期或连接失败不留部分节点。
- AI 查询定义后可一次提交数量并完成连线。批次提供新节点端口的模板与顺序引用，解析后落到稳定实例 ID；
  该临时引用仅用于建图批次，不把可变序号存成正式连线身份。回执仍交付真实端口地址。

例如回归节点的 X 模板若为 `x`，`"portCounts": { "x": 4 }` 创建四个 X Pin；Y 保持一个。
实际模板 key 由创建前查询返回，GUI 和 AI 不凭显示名猜测。

### 批量编辑与创建前查询

继续复用 `apply_graph_edit`、`clientId` 别名、幂等回执和单批撤销。AI 可以一次请求创建多个带参数节点，再通过别名连接；不为此新增另一套图构建 DSL 或要求先发布空节点。批次内按依赖形成候选状态，只提交完整批次，不因中间节点暂时未连接而拒绝整个意图。

扩展现有目录查询的按需定义读取，从冻结注册表提供参数 key、类型、默认值、固定约束、条件显隐，以及与输入相关的约束说明。GUI 创建表单与 AI 读取共用定义投影；搜索摘要保持有界，详细定义按需交付，不能把全目录协议每次都塞给模型。

`inspect_graph` 和编辑回执需要提供当前候选项是否已知、参数待验证或不匹配的原因，以及实际诊断。工具提交成功只表示配置已经提交，不等于节点可以执行。模型无需读源码或先创建临时节点来猜测参数。

GUI 保留直接创建，同时增加创建前配置入口。局部表单取消时不提交节点；提交时复核捕获的图、面板、来源端口与资源版本，不能因切换标签页而创建到另一张图。创建失败保留可修正的表单输入，正式参数以提交回执为准。

- [x] 明确 Transform 的行身份与对齐检查；Apply 保留来源组信息，输出冲突不静默覆盖。

实现采用以下契约；自动验证证据及用户验收确认见文末：

| 项目          | 契约                                                                                                         |
| ------------- | ------------------------------------------------------------------------------------------------------------ |
| 分组数据      | GroupBy 持有源关系及分组键；显式运行边界保留稳定源结果。现有固定聚合继续使用原生查询计划。                   |
| 组顺序及 Null | 分组键按确定顺序排列，Null 作为普通组键参与；每组内部保留源行顺序。                                          |
| 函数输入      | 首批 Apply/Transform 接受一个 DataFrame 参数并返回 DataFrame 的图函数；组内表包含分组键。                    |
| Apply 来源    | 输出前置带 `group.` 前缀的分组键列，前缀可配置；名称冲突明确报错。                                           |
| 输出一致性    | 检查每一组返回值的列顺序、名称、物理类型及语义；不一致时带组编号和函数位置失败，不静默取第一组或补 Null。    |
| Transform     | 返回值必须保留组内全部行及其对应顺序，不能靠行数相同证明对应关系；按源行身份恢复全表顺序。返回函数生成的列。 |
| 空输入        | 用空表调用一次纯图函数以确定输出结构，最终返回零行；无法处理空表的函数明确失败，不凭空推测列结构。           |
| 计算与持有    | 按组顺序处理，复用函数帧和原控制对象；引擎按批写入临时 Arrow 存储，不为每组复制完整来源表。                  |

实现边界为：Relational Contract 声明分组视图及分组读写会话；Database Engine 负责排序、临时存储、
行对应和结果合并；Execution 绑定每组实参、调用函数并保留错误组位置。Kernel 的 GroupBy 只构造图无关的
分组值，Catalog 声明节点参数和接口；函数代码不进入关系引擎或叶内核。

阶段依赖为 `P1 → P2 → P3 → P4 → P5 → P6 → P7`。每阶段完成后先交付可观察行为与证据，不提前把后续状态、接口占位或迁移层放进当前实现。
