我倾向于保留统计人员熟悉的方法名称，同时增加清楚的目录层级，并把“数据类型、研究目的、拟合/诊断/预测”等作为筛选条件。还需要调整节点的展示粒度：例如 LMM、随机截距和随机斜率属于同一方法族，适合呈现为主方法与预设，而不是同层的几个独立方法。
**目前的分类确实需要重构。** 时间序列、生存分析、Meta 分析等类别本身很合理；主要问题在于命名、层级、类别边界和节点粒度。前一轮补齐执行能力时，我沿用了原有目录，这部分还需要单独设计。

从专业统计人员的使用习惯来看，目录应该帮助用户回答三个问题：**我要解决什么问题？我的数据有什么结构？这个方法适不适用？**

可视化、概率分布和基础运算继续作为独立工具入口。这里的上级分区用于浏览，方法是否适用还要由数据条件和模型要求决定。

有几处边界需要特别说明：

- **方差分析与回归有共同的线性模型基础。** 可以保留 ANOVA 这个专业人员熟悉的入口，同时复用模型能力，避免维护两套等价实现。
- **面板、纵向、多层存在交叉，但不能直接合并成一个算法。** GEE、混合模型和面板固定效应需要保留清楚的方法差异。
- **相关与一致性应明确区分。** Pearson、Spearman 用于关联；Kappa、ICC 等进入测量与一致性分析，并提供交叉搜索。
- **普通中介、调节和路径分析不应自动归为因果推断。** 目录名称不能让用户误以为建立路径模型就已经识别了因果效应。

另外，**节点粒度也应该一起梳理**。现在 LMM、随机截距、随机斜率、Logistic 混合模型等并列，会把方法族、模型结构和具体分布预设展示成同一级概念。更合理的展示是“混合效应模型 → 模型类型与常用预设”。AIC、BIC 则适合归入模型比较工具；它们是否继续作为独立节点，要看独立输出和组合计算的实际价值。

为了处理交叉归属，我会采用 **一个主分类，加多个检索标签**：

| 标签维度 | 示例                                                       |
| -------- | ---------------------------------------------------------- |
| 研究目的 | 描述、比较、关联、预测、因果效应                           |
| 响应变量 | 连续、二元、有序、多分类、计数、事件时间                   |
| 数据结构 | 独立、配对、重复测量、聚类、面板、时间序列、空间、复杂抽样 |
| 操作阶段 | 拟合、诊断、比较、预测、解释                               |

例如，**Logistic 混合模型**的主位置是“重复测量、面板与多层模型 → 混合模型”，同时可以通过“二元结果”“Logistic”“聚类数据”搜索到；用户连接一个已拟合模型后，还能直接看到适用的诊断和后估计节点。所有入口指向同一个节点身份和实现。

这种组织方式既保留专业人员熟悉的方法名称，也能让用户沿着实际分析问题找到方法。
