# AI Harness 领域工具重构计划

> Status: Planned
> Scope: 项目资源、图、节点、连接、数据库、思维导图、Markdown 文档、图表和运行结果的模型工具设计、实施顺序与验收
> Canonical owners: 本文拥有计划；当前 Harness 契约由 [Harness Core](../../crates/yss-harness-core/README.md) 和各资源模块的源码、README 维护
> Update when: 工具边界、阶段范围、实施进度或验收条件改变时

本文是目标方案与实施记录，工具目录不表示已经全部验收。P0–P5、P6 的图表工具及代表性任务测量已完成下文记录的聚焦验证，剩余工作为 P6 的 Assistant 人工界面验收，具体操作与通过标准见 14.4。后台测量与契约检查不能替代该验收。

当前原生调用链为 GPUI → ApplicationServices / 类型化 Harness 用例 → Core / Gateway → 原领域 owner。
阻塞业务在 worker 执行，持久事件与 Assistant 读投影由 `yss-harness-contract` 交付宿主；
工作台根 DockArea 只拥有拓扑。参考界面记录不代表 GPUI 已验收，14.4 的全部人工项继续开放。

## 1. 目标与范围

将模型可见工具按业务对象和明确动作拆开。模型应当能够直接表达“创建这些节点”“读取这张结果表”“替换这一段文字”，不需要了解通用编辑操作枚举、文件 JSON 结构或前后端同步协议。

已确定的方向：

- 保留节点画布。节点允许未连接时配置参数和 Pin 数量，连接后再提供已知类型、列和候选项约束。
- 图级工具保留 `inspect_graph`、`validate_graph`、`execute_graph` 三个入口；节点类型、节点实例、连接分别处理。
- 区分可创建节点类型和图中已存在节点：`browse_nodes` / `inspect_node_type` 与 `find_nodes` / `inspect_nodes`。
- 使用 `create_nodes` 等明确工具替代模型侧 `apply_graph_edit`；内部继续使用现有原子批量编辑能力。
- `inspect_resource` 只读取资源身份和轻量信息，不再承担内容读取。
- JSON 资源通过业务投影读取、通过类型化命令修改；Markdown 通过文本工具读取和修改。
- revision、expected revision、内容哈希、幂等键、当前项目会话绑定等同步信息由工具层自动处理，不进入模型输入、工具说明、返回值或历史重放。
- 结果按需读取，执行按用户需求触发。连接、查看和配置不会隐式执行图。

函数定义、函数签名、函数调用节点和分组函数机制不在本轮重新设计范围。已有函数能力保持原职责；通用接口清理不能顺带删除仍在使用的函数分支。节点执行机制继续遵循[节点独立配置与分步执行计划](NODE_AUTHORING_AND_EXECUTION.md)，不重新开启已完成工作。

本计划也不增加 Python 单元、外部 MCP、后台自主运行、对话转长期记忆或隐式 computer-use。现有知识检索、任务委派和界面意图可以继续使用。

## 3. 模块职责、数据流和依赖

### 3.1 在现有模块内分工

| 层                                         | 职责                                                                     | 不应承担的职责                                      |
| ------------------------------------------ | ------------------------------------------------------------------------ | --------------------------------------------------- |
| `yss-harness-contract`                     | 按领域声明模型输入、精简结果、稳定错误和工具描述所需契约                 | 资源读写、模型供应商适配                            |
| `yss-harness-core`                         | 工具目录、角色能力筛选、授权、业务引用绑定、调用生命周期、账本与模型投影 | 第二套图状态、数据库副本或文档持久化                |
| `yss-harness-rig`                          | 将工具契约注册到 Rig，接收调用并转交 Core                                | 重复定义业务 schema、资源同步逻辑和权限判断         |
| `yss-application`                          | 将明确工具命令适配为原业务用例，组织跨 owner 的必要流程                  | 在适配器中直接拼装和覆盖资源 JSON                   |
| Graph / Database / Project / Results owner | 校验、查询、原子修改、执行、保存和权威回执                               | 依赖模型提示词或前端临时状态实现一致性              |
| GPUI Assistant                             | 消费类型化事件/读投影，显示工具名、业务参数、进度、耗时、结果和失败 | 重新执行工具、补 revision、成为提交是否成功的判断源 |

模型契约按资源、图、节点、连接、数据库、Mind、文档、结果等领域组织；具体文件粒度按现有目录调整，不为了工具数量增加 crate 或独立服务。

### 3.2 调用链

模型意图 → Rig schema 校验 → Core 授权和上下文绑定 → Application 用例 → 原业务 owner 校验与提交 → 权威回执 → Core 持久账本、模型结果和类型化原生事件。

一次成功修改的回执用于更新内部观察状态，后续调用复用它，不要求模型再调用一次检查工具来“刷新版本”。读取与写入依赖的版本始终在 Rust 侧保留。

如果写入基于此前读取，而资源已经被用户或另一任务修改，应返回可操作的冲突说明和需要重新读取的业务范围。禁止简单读取最新 revision 后强行重试旧修改。没有此前观察的新操作，也由工具层在原 owner 的事务边界内建立一致的执行依据。

图编辑批次继续调用已有 Graph 原子编辑内核；数据库新增批次进入 Database owner；Mind 继续使用其模型校验和批次提交。各领域不绕开原保存、撤销、发布和取消语义。

## 4. 共同工具契约

### 4.1 输入与 schema

1. 工具名表达单一业务动作，避免重新引入 `action + 任意 payload` 或包揽所有资源类型的联合参数。
2. 资源引用复用业务 `resource: { kind, id }`；图、数据库、文档等参数在 schema 中收窄允许类型。文件资源继续使用真实资源路径身份，数据库继续使用真实数据库身份。
3. 节点、Pin、连接、主题和结果使用工具返回的真实标识。批量创建可使用仅在当前调用内有效的 `clientId` 别名；返回别名到真实标识的映射。
4. 模型可见 DTO 与内部执行 DTO 分离。业务对象 ID、运行 ID 和分页游标可以出现；同步版本、项目会话令牌、内部提交凭据不出现。
5. 结构化工具 schema 从类型契约生成并复用现有 schema 能力；节点参数 schema 来自节点定义，不在 Harness 维护第二份参数字典，也不直接暴露 UI 编辑器配置。
6. 参数缺省、空值和显式清空具有不同语义。更新工具应当只改变明确指定的字段。
7. 错误指出工具、业务对象、无效字段或冲突范围，并给出下一步所需信息。不要把内部请求、密钥、完整资源或同步字段序列化进错误文本。

### 4.2 默认精简、定向展开

| 内容                               | 默认返回                                 | 展开方式                                    |
| ---------------------------------- | ---------------------------------------- | ------------------------------------------- |
| 资源索引、类型目录、节点和连接列表 | 身份、名称和少量定位信息                 | 搜索、过滤、分页                            |
| 图                                 | 计数、执行状态和诊断计数                 | 查询指定节点、连接或诊断范围                |
| 节点类型                           | 指定类型的配置 schema、默认值和 Pin 约束 | 批量指定需要的类型，避免返回整个目录 schema |
| 数据库或结果表                     | schema、统计概览或选定列的有限行         | 列投影、行分页；数据库按业务查询条件过滤    |
| Mind                               | 根主题和有限深度、有限数量的大纲         | 主题搜索、按 ID 读取或展开子树              |
| Markdown                           | 定位后的正文片段                         | 按章节、字符范围或搜索命中读取              |

分页返回实际范围、`hasMore` 和可直接使用的继续位置；计数未知时明确未知，不能用零替代。数量较多的诊断、schema 列和大纲本身也需要分页。列表默认不夹带正文、运行值或全量节点定义。

Markdown 正文以约 8,192 个 Unicode 字符作为初始默认页，确需更多时可请求约 16,384 字符；这是待实测的读取起点，不是文件大小上限，也不是已证明最优的 token 数。结合当前模型上下文余量调整实际返回量，返回真实下一位置，不让模型自行猜偏移。优先在段落、标题边界切分；超长段落或代码块允许续读，并明确本页只是片段。

结构化内容按实体、列和行分页，不能截断 JSON 字符串后交给模型。`hasMore=true` 只表示还有内容，不代表任务必须读完整表。完整数据始终留在原 owner；返回分页不能变相成为计算行数、内存、工具调用次数或整轮运行时长的限制。

### 4.3 批次、回执与保存

- 每个批量修改调用先验证整个批次，再一次提交；失败不留下部分节点、半棵树或只改了一半的单元格。需要新事务能力时先补 owner。
- 同一个调用内的批量修改，在原 owner 支持历史时形成一个撤销单位。不同工具调用之间不承诺整体事务，不增加模型可见 begin/commit 协议。
- 跨资源任务逐次报告真实完成状态；后续失败不能把此前已经提交的修改描述为回滚。
- 回执包含变更对象、创建别名映射、必要的实际 Pin、受影响连接、保存/脏状态和后续可用引用。不能每次修改都附带整张图或整篇文档。
- 大批次回执允许分页查阅详细变更，但必须明确已提交数量和如何取得真实 ID；不能静默截断关键创建映射。
- 取消、超时或连接中断后，以已有账本和 owner 回执判断是否提交；结果未知时不盲目再次创建、导入或导出。

统一使用 `save_resource` 表达显式保存，实际语义仍由资源 owner 决定：

| 资源            | 本计划保持的保存边界                                            |
| --------------- | --------------------------------------------------------------- |
| Harness 图编辑  | 沿用现有批量修改与持久化原子提交；不推广为所有 GUI 操作自动保存 |
| Mind / Markdown | 编辑产生 dirty 状态，显式保存完成持久化                         |
| Chart           | 配置修改沿用现有立即持久化                                      |
| Database        | 沿用数据库自己的编辑提交、历史与保存/checkpoint 用例            |

### 4.4 耗时、权限与历史

每次工具调用都通过现有事件记录开始、结束、状态和耗时。图执行另行提供真实运行耗时，排队、等待和工具往返耗时不冒充节点计算耗时；仍在执行时提供经过时间和进度。

角色工具集从同一目录生成，按角色和已确定的任务资源范围筛选，避免每个模型请求携带全部领域 schema。筛选不替代后端授权，也不能让一次任务中必要工具无故消失。先复用当前角色能力机制，不额外建设一套工具搜索服务。

同一次调用的模型输入、实时结果、前端显示和上下文重放遵守同一公开契约。账本保留真实公开工具名与业务输入，并关联内部执行和提交证据；复用现有账本，不新增平行存储。历史工具记录是已发生事实，不应依赖某个旧工具仍可调用才能展示。按当前契约实现，不增加旧格式迁移、旧协议适配或清空用户历史的步骤。

## 5. 项目资源工具

项目资源工具只管理资源生命周期，不读取或修改具体资源正文。

| 工具                 | 主要输入                          | 返回与边界                                                                          |
| -------------------- | --------------------------------- | ----------------------------------------------------------------------------------- |
| `list_resources`     | 可选 kinds、名称/路径 query、分页 | 资源索引；不搜索正文、不返回完整资源                                                |
| `inspect_resource`   | resource                          | 身份、名称、类型、dirty 等轻量信息；没有 `metadataOnly`、`graphView` 或正文分页参数 |
| `create_resource`    | kind、name                        | 新资源引用和必要初始引用，如 Mind 根主题；数据库交给导入工具                        |
| `rename_resource`    | resource、name                    | 实际新名称和新 resource；文件路径变化时后续使用回执，不能猜新 ID                    |
| `duplicate_resource` | resource、可选 name               | 新资源引用；沿用原 owner 的复制与 ID 分配规则                                       |
| `delete_resource`    | resource                          | 实际删除和引用影响；沿用原资源删除语义                                              |
| `save_resource`      | resource                          | owner 确认的保存结果、dirty 状态；不把“命令已接受”当成已保存                        |

创建覆盖已有图、Chart、Mind、Doc 生命周期；函数资源现有生命周期不因此改版。自定义复制名称若现有 owner 不支持，需要补齐一致的复制用例，不能复制成功后重命名失败，却向模型报告整次操作失败且没有副作用。

## 6. 图、节点和连接工具

### 6.1 图级工具

| 工具             | 主要输入                      | 返回与边界                                                                     |
| ---------------- | ----------------------------- | ------------------------------------------------------------------------------ |
| `inspect_graph`  | graph                         | 图概览、节点/连接计数、诊断计数和运行状态；不返回完整节点、所有 Pin 或结果数据 |
| `validate_graph` | graph、可选 nodeIds、诊断分页 | 全图或指定执行范围的 readiness 与定位诊断；不执行节点                          |
| `execute_graph`  | graph、可选 nodeId、mode      | 全图或指定节点执行；状态、耗时、失败位置和精简结果引用                         |

节点执行模式沿用 `currentInputs` 与 `dependencies`：前者使用当前可用输入执行目标节点，后者按需求执行其依赖。输入缺失和结果已过期必须明确；不能在前者中偷偷运行上游。未指定 nodeId 时使用原全图执行语义。

局部校验必须与局部执行需求对应，无关分支错误不应阻塞当前可执行节点。当前整图校验之外的作用域支持是待补能力，不能只在工具 schema 加 nodeIds 而底层仍无条件校验全图。

### 6.2 节点类型工具

| 工具                | 主要输入              | 返回与边界                                                                  |
| ------------------- | --------------------- | --------------------------------------------------------------------------- |
| `browse_nodes`      | query、category、分页 | 可创建类型的 typeId、名称、类别和简短用途；不默认返回所有配置 schema        |
| `inspect_node_type` | typeIds               | 指定类型的参数 schema、默认值、Pin 模板、固定/可配置/派生数量约束和必要说明 |

节点类型工具不要求先创建节点、连接 DataFrame 或执行图。`inspect_node_type` 不读取实例结果；多个类型可以一次查询，避免逐个往返。

### 6.3 节点实例工具

| 工具              | 主要输入                           | 返回与边界                                                                        |
| ----------------- | ---------------------------------- | --------------------------------------------------------------------------------- |
| `find_nodes`      | graph、名称/typeId 等过滤、分页    | 已存在节点的 ID、类型、名称和简短状态                                             |
| `inspect_nodes`   | graph、nodeIds、需要的字段         | 实际参数、Pin、连接摘要、已知 schema 和动态候选项；不返回 Pin 数据值              |
| `create_nodes`    | graph、nodes、可选初始 connections | 批量创建；每个节点可给 clientId、typeId、parameters、portCounts、label 和可选位置 |
| `update_nodes`    | graph、节点更新列表                | 批量修改明确指定的参数、字面量、名称和可配置 Pin；不隐式运行                      |
| `delete_nodes`    | graph、nodeIds                     | 删除节点及其关联连接，回执说明受影响对象                                          |
| `duplicate_nodes` | graph、nodeIds、可选位置偏移       | 复制选中节点及选中集合内部的连接，返回真实新 ID 和 Pin 映射                       |
| `move_nodes`      | graph、节点位置列表                | 一次提交布局变更；不改变数据或触发计算                                            |

创建节点的流程应当是“查类型 → 一次创建并配置 → 按需执行”，不要求“创建 → 连接 → 才能填写参数”。例如回归节点的 Y 固定为 1、X 可设为 5，则在 `create_nodes` 中直接设置 X 模板数量为 5，并同时提交参数。实际模板 ID 和参数键必须使用类型查询结果，不能把显示名称当成稳定键。

`portCounts` 只控制声明为可配置的模板，固定和派生 Pin 不接受人工改写。缩减已有 Pin 数量时保留哪些实例、移除哪些实例必须确定；受影响连接沿用 owner 的明确规则，回执不得隐藏断连。

初始连接可以引用当前调用内的节点别名和 Pin 模板实例，也可以引用已有节点的真实 Pin。节点和这些连接构成一个原子批次，任一参数或连接无效则全部不创建。跨后续调用时必须使用返回的真实标识。

连接后展示可确定的参数约束；未运行而无法确定的 DataFrame 列应显示为未知或待执行，不能当成空列集合拒绝参数。静态可推导的元信息仍可提供，但不能伪装成实际运行输出。

### 6.4 连接工具

| 工具                 | 主要输入                       | 返回与边界                               |
| -------------------- | ------------------------------ | ---------------------------------------- |
| `find_connections`   | graph、可选节点/Pin 过滤、分页 | 连接 ID 与精确起止 Pin                   |
| `create_connections` | graph、连接列表                | 一次校验并创建，返回真实连接标识         |
| `delete_connections` | graph、connectionIds           | 一次删除指定连接                         |
| `update_connections` | graph、连接及新端点列表        | 原子重接现有连接，覆盖原批量移动连接能力 |

不要求模型通过“先断开、再连接”的两个调用实现一次重接。批量断开某个节点或 Pin 可先查其连接，再一次删除；初始建图则优先放入 `create_nodes` 的初始连接。

### 6.5 图常量

现有图编辑还承载常量操作，替换 `apply_graph_edit` 时不能遗漏：

| 工具                | 主要输入                              | 返回与边界                                                        |
| ------------------- | ------------------------------------- | ----------------------------------------------------------------- |
| `find_constants`    | graph、名称过滤、分页                 | 常量身份、类型和简短值概览                                        |
| `inspect_constants` | graph、constantIds、可选值读取范围    | 指定常量的类型化值和说明；表格、长文本按需分片读取                |
| `create_constants`  | graph、常量声明列表、可选引用节点配置 | 原子创建常量及指定的初始引用节点，返回真实常量与节点引用          |
| `update_constants`  | graph、常量更新列表                   | 校验类型与引用影响后一次提交                                      |
| `delete_constants`  | graph、constantIds                    | 沿用现有删除语义，保留引用节点并报告失效影响，支持原 owner 的撤销 |

已有常量的引用节点通过 `create_nodes` 的对应节点类型和常量引用配置创建，由适配层转交原常量引用用例。创建常量时同时创建首个引用节点的现有能力继续保留。大常量值按需定向读取，不在列表附带完整表格；读取或修改均使用业务值契约，不能在 Harness 直接修改底层 JSON 成员。

## 7. 数据库工具

一个 Database 资源对应一份数据集，不在模型层虚构“数据库下面还有多张可任意操作的表”的层级。大数据查询和转换留在 Rust 数据模块，工具只返回投影。

### 7.1 查询、导入与导出

| 工具                      | 主要输入                                   | 返回与边界                                                  |
| ------------------------- | ------------------------------------------ | ----------------------------------------------------------- |
| `inspect_database`        | database                                   | 数据集概览、可用行列计数和状态，不附完整 schema 或数据      |
| `inspect_database_schema` | database、可选 columns、分页               | 类型、语义和列元信息；宽表可分批查询                        |
| `profile_database`        | database、columns、所需指标                | 指定列的数据质量和统计摘要，不默认生成所有列完整报告        |
| `read_database_rows`      | database、columns、可选 filter/order、分页 | 选定列数据与稳定 rowId；按原 owner 的查询语义返回           |
| `import_database`         | name、类型化 source                        | CSV、Parquet、Excel 或 SQL 来源导入，返回 Database resource |
| `export_database`         | database、格式、目标                       | 实际导出结果，沿用现有导出能力和目标约束                    |

filter/order 需要使用数据 owner 支持的类型化查询条件；尚未支持的条件是实现任务，不能只在 Harness 接受后忽略。不开放任意 JSON 修改或用任意写 SQL 代替业务命令。来源认证沿用现有连接配置，工具输出、日志和错误不得回显密钥。

### 7.2 行与列编辑

| 工具                   | 主要输入                             | 返回与边界                                       |
| ---------------------- | ------------------------------------ | ------------------------------------------------ |
| `insert_rows`          | database、行值列表、可选插入位置引用 | 一次插入并初始化内容，返回稳定 rowId             |
| `update_cells`         | database、rowId/column/value 列表    | 一次校验类型并更新单元格                         |
| `delete_rows`          | database、rowIds                     | 按稳定身份删除，不能把当前排序页的行号当原始行号 |
| `create_columns`       | database、列声明列表                 | 一次新增列，沿用 owner 的类型和默认值规则        |
| `rename_columns`       | database、列重命名列表               | 一次校验命名冲突和相关影响                       |
| `delete_columns`       | database、columns                    | 一次删除指定列并报告影响                         |
| `cast_columns`         | database、目标类型列表、显式转换选项 | 返回实际转换结果和失败信息，不静默改写失败值     |
| `set_column_semantics` | database、列语义列表                 | 更新业务语义，遵循数据模块约束                   |

现有编辑器需要的行位置、版本或查询基线由工具层绑定。模型只拿到稳定行引用；读后发生并发修改时不能将同一个位置误写到另一行。

批量插入带初始值、批量单元格更新及其他批次能力必须在原 Database owner 内支持整体校验和提交。验收应故意让最后一个操作失败，确认前面没有部分生效；不能用循环单次编辑伪造批次成功。这里不增加任意表达式执行器，复杂分析仍通过已有节点和执行机制完成。

## 8. 思维导图工具

思维导图读取的是主题树，修改的是主题语义与父子关系，模型不接触原始 JSON。

| 工具               | 主要输入                             | 返回与边界                                                         |
| ------------------ | ------------------------------------ | ------------------------------------------------------------------ |
| `inspect_mind`     | mind、可选根主题/depth、分页         | 根主题、计数和有限大纲                                             |
| `find_topics`      | mind、query、可选子树范围、分页      | 匹配主题 ID、内容摘要和定位路径                                    |
| `inspect_topics`   | mind、topicIds                       | 主题正文、父子关系和业务引用                                       |
| `create_topics`    | mind、主题列表                       | 可含初始正文、引用、父主题及调用内别名，一次创建多层结构           |
| `update_topics`    | mind、主题更新列表                   | 更新正文或显式设置/清空引用                                        |
| `move_topics`      | mind、主题与目标父主题、可选同级位置 | 原子调整树关系，检查根、环路和父主题存在性                         |
| `delete_topics`    | mind、topicIds                       | 删除指定主题及其子树，回执报告实际范围；根主题删除通过删除资源处理 |
| `duplicate_topics` | mind、子树根 ID、目标父主题          | 复制子树并分配全新主题 ID，不复用原主题身份                        |

同级顺序沿用原模型规则；不引入不属于持久化模型的画布坐标、展开状态或前端布局参数。失效的外部引用可以作为原始内容保留并提示，不等价于树结构非法。

主题查找、定向大纲和子树复制中现有 owner 尚未提供的部分，需要在那里增加用例。编辑完成返回 dirty，显式 `save_resource` 后才作为已持久化交付。

## 9. Markdown 文档工具

Markdown 是文本资源，可以直接编辑文本；这里的“直接”指经过 Doc owner 的文本命令，不是绕过资源生命周期写文件。

| 工具                    | 主要输入                            | 返回与边界                                               |
| ----------------------- | ----------------------------------- | -------------------------------------------------------- |
| `inspect_document`      | document、可选大纲范围、分页        | 标题、大纲、正文长度等文档结构信息，不返回整篇正文       |
| `read_document`         | document、章节引用或字符范围、limit | Markdown 片段、实际范围、继续位置和是否完整              |
| `search_document`       | document、query、可选范围、分页     | 命中位置和有限上下文，帮助确定唯一替换片段               |
| `replace_document_text` | document、精确替换列表              | 一次提交多个 oldText/newText 替换；每一步必须唯一命中    |
| `append_document`       | document、text                      | 追加正文，保留已有内容，返回实际变更范围                 |
| `write_document`        | document、完整 markdown             | 明确整篇替换或初始化；不能把某页读取结果当成完整正文回写 |

大纲和章节引用由当前 Markdown 派生，不新增一份持久化 AST。重复标题应能通过返回的章节引用区分；文档变动后旧定位不能悄悄落到另一段。

优先采用“搜索 → 定向读取 → 精确替换”，不要求为了修改一段文字先读取整篇文档。替换列表按顺序作用于同一份暂存正文，任何一步零命中或多命中则整个批次不提交；空 oldText 不作为插入捷径，追加使用独立工具。

已有文档的整篇重写必须是明确的操作意图，并沿用内部观察基线和冲突检查。保持 Markdown 原文本、Unicode 内容和代码块；正文超过一个读取页不影响整篇写入。修改与保存分开，报告交付以 `save_resource` 的实际结果为准。

## 10. 运行结果工具

图检查解决“图是什么”，结果查询解决“运行产生了什么”。Pin 绑定到的当前结果和保留的历史运行结果必须区分。

| 工具                 | 主要输入                                 | 返回与边界                                                    |
| -------------------- | ---------------------------------------- | ------------------------------------------------------------- |
| `list_graph_results` | graph、可选 runId/nodeIds/Pin 范围、分页 | 结果引用、来源、类型、运行和有效性摘要，不附大表              |
| `inspect_result`     | 完整 resultRef                           | 标量、结果结构、表引用、schema 摘要和必要概览；大 schema 分页 |
| `read_result_table`  | 完整 tableRef、columns、分页             | 选定列的表格数据、实际范围、继续位置                          |

模型完整传递工具返回的 resultRef/tableRef，不拼接内部 namespace、session 或结果子路径，也不构造 `part: "null"`。如果现有内部引用含同步字段，模型投影提供可以原样回传的业务引用，解析仍指向原 ResultStore，不能建立第二套结果身份。

引用已过期、结果已清理、运行未完成、指定表不存在应分别说明。旧运行结果如果仍保留可以读取，但不能描述成当前 Pin 的有效输出。查询不触发重新计算；需要新结果时显式调用 `execute_graph`。

检验和事后比较产生的大表不默认全部读取。报告可先读取方法、样本量、关键统计量和所需对比，再定向取表格，避免多次完整图检查和重复搬运全列结果。

## 11. 图表与保留的公共能力

### 11.1 独立图表资源

| 工具            | 主要输入              | 返回与边界                                                     |
| --------------- | --------------------- | -------------------------------------------------------------- |
| `inspect_chart` | chart                 | 类型化配置、数据源和可配置字段                                 |
| `update_chart`  | chart、明确指定的设置 | 更新数据源、图表类型、轴等现有配置，一次校验并沿用原持久化语义 |

Chart 资源与图中的绘图节点分开。当前支持的图表类型和参数直接由 schema 声明，不另建重复目录；不借本轮扩展全部可视化类型，也不承诺尚未接入的模型图表截图或预览工具。

### 11.2 历史、知识、界面与编排

| 能力                                      | 本轮处理                                                                                          |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `undo_resource` / `redo_resource`         | 从通用编辑中拆出；只支持已经拥有历史的 Graph、Database，并沿用各 owner 语义，不虚构项目级统一撤销 |
| `search_knowledge` / `read_knowledge`     | 保留检索与读取分工，不并入资源正文工具                                                            |
| `request_ui_intent` / `inspect_ui_intent` | 保留声明式界面意图；区分已请求、已应用、被拒绝，不增加隐式 computer-use                           |
| `delegate_task` / `followup_task`         | 保留现有委派控制，不用新工具数量限制或固定调用次数切断正常任务                                    |
| `propose_statistical_plan`                | 保留统计计划能力，不与项目资源计划文件混为一谈                                                    |

角色方面保持现有 Data→Database、Stats→Graph、Plot→Chart、Report→Doc 的内容写入边界；Manager 和 Review 不因为新工具注册获得额外内容写权限。Mind 写入纳入 Report 角色，并同步其任务说明、授权与完成判据；仅交付 Mind 的任务不能被硬性要求另建 Markdown 报告。具体资源创建、保存和删除仍通过现有授权规则判断。

## 13. 分阶段实施

每阶段先补必要 owner 能力，再切换模型契约与消费方，完成聚焦验证后更新本计划和对应模块 README。未勾选条目仍需完成，阶段内的部分进展不能替代整阶段验收。

阶段完成摘要（2026-10-06 的业务验证记录，非本次检查）：

- 项目资源工具已贯通 Contract/Core/Rig/Application。轻量检查读索引或元信息，不打开正文；
  创建/复制在原事务确定名称和身份，回执与提交版本一致，失效后不强行刷新基线重试写入。
- 节点类型/实例、连接、常量与图历史已切换明确工具。参数、多 X Pin、初始连接同批提交，
  无效末项整体回滚；复制回执给出实际 ID，重接保留连接 ID，撤销恢复真实身份。
- 校验与执行使用实际依赖范围；概览与结果表读取分开，完整 resultRef/tableRef 贯穿授权、
  实时投影与重放。运行计时来自原 RunRegistry，不用工具往返时间冒充计算时间。
- 数据行列操作由 Database 原 owner 原子提交，稳定 rowId 支撑排序分页后的修改；
  列投影、AND 筛选、多列排序、schema/profile、导入导出与 checkpoint 保持原授权和版本边界。
- Mind 提供有界大纲/搜索/主题查询、批量树编辑与分支复制，真实 ID 和完整删除范围进入回执；
  Doc 使用结构/范围查询与精确文本事务，章节定位绑定读取基线。两者编辑与显式保存区分。
- Chart inspect/update 使用类型化配置与立即持久化；省略保留，轴的 null 明确清空，
  改数据源核对读取授权。六角色注册、Ask 模式与知识/意图/委派能力仍按现有策略筛选。
- 绑定、解码、准入、控制工具拒绝、取消和终态都进入原调用生命周期；未确认提交保持结果未知，
  恢复不重做写操作。真实模型测量补齐 Manager/Review 的 validate_graph 及 Report 的获准数据读取。
- 当时已有聚焦业务回归及代表性模型任务证据，详见 14.2；完整工作区和 UI 不由局部结果推定通过。
  默认并发测试初始化曾出现内存访问异常，独立标准库程序和两版 Rust 也有复现记录；
  顺序运行通过不能证明默认并发已通过，环境根因仍独立排查。

详细实现日志由 Git 保留，当前工具目录以 Harness Core README 为准；原生工具卡和历史重放仍待 14.4 验收。

## 14. 验证与验收

### 14.1 必须保护的行为

| 验收场景          | 判断标准                                                                               |
| ----------------- | -------------------------------------------------------------------------------------- |
| 公开工具契约      | schema、错误、实时结果与重放只暴露业务信息；无需模型填 revision 或内部会话绑定         |
| 轻量资源检查      | 大文档、大 Mind 和大图的元信息查询不读取完整正文；重命名回执能直接用于后续调用         |
| 无连接创建节点    | 参数和可配置 Pin 数量可在创建时提交；未知 DataFrame schema 不被当成空 schema           |
| 原子建图          | 同批节点、参数和初始连接全部成功或全部不生效；创建结果可直接继续使用                   |
| 分步执行          | currentInputs 不隐式重跑上游；dependencies 只执行所需依赖；无关分支不错误阻塞          |
| 查询与结果隔离    | 图和节点查询不运行计算，不附全量 Pin 输出；结果查询保留原运行来源和有效性              |
| 图编辑覆盖        | 连接重接、常量引用、节点复制和撤销/重做不因拆工具丢失                                  |
| 数据库身份与批次  | 排序、筛选、分页后按稳定行身份正确编辑；末项失败时整批无部分提交                       |
| Mind 树语义       | 环路、错误父节点和根处理正确；删除范围明确；复制主题 ID 全新；失效外部引用不误判为坏树 |
| Markdown 精确修改 | 唯一匹配才修改；多处或零命中不部分提交；Unicode 范围正确，片段不覆盖整篇               |
| 保存与中断        | dirty、已保存和提交未知明确区分；取消或重试不重复创建资源；已提交事实保留              |
| 角色与交付        | 未授权角色不能写入；Mind 任务可以独立完成并保存，不被要求附加 Doc                      |
| 耗时和显示        | 每次工具成功、失败、取消都有可信时间状态；节点运行时间与等待时间含义明确               |

测试通过对应 owner 或公开契约边界验证真实行为，复用现有覆盖。每新增测试先指出独立回归风险，不增加仅搜索旧名字或复制实现结构的测试。

### 14.2 代表性任务对比

1. 大图中寻找一个回归节点，修改配置、执行该节点并读取 VIF 或异方差检验摘要。
2. 创建并配置一组节点，设置多输入 Pin 并建立连接；故意引入一条无效连接验证整体失败。
3. 在数据库中筛选并修改若干行，再批量改列；验证并发变化和转换失败。
4. 创建多层思维导图，移动、复制和删除一个分支，保存后重新读取。
5. 读取含大表的多个统计结果，生成长 Markdown 报告，再只修改其中一节。

在相同数据、任务、模型和配置下记录调用次数、模型工具 schema 体积、工具返回字符数、可获得的实际 token 用量、重复读取次数、失败/重试次数及耗时。不预设未经测量的节省比例；重点确认完成同一任务不再反复读取完整图、所有结果表或全文。
