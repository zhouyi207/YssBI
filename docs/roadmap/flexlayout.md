## 当前基线

- 根 DockArea 唯一拥有面板放置、排序、选中分组、边缘尺寸和折叠状态；菜单、底栏与视图从同一拓扑派生。
- 原生分屏移动现有编辑器，不复制文档或实体。重置将已打开资源归回默认区域，保留未保存输入和结果租约。
- 资源索引、当前图、历史、运行与结果分别留在 Project/Graph/Execution；Assistant 会话归 Harness。
  弱引用面板查找表不是第二布局模型，持久布局也不保存业务数据或把临时结果租约恢复成有效结果。
- 设置与日志使用独立非模态原生窗口；表单和确认由现有 `modal_window` 以原生 Dialog 窗口承载，
  父窗口不绘制 Dialog 遮罩。文件/目录选择使用系统入口，长耗时业务在 worker 执行。
- 结果独立窗口继续经原 Application 取得和释放租约；关闭一个窗口不应清除其他消费者持有的结果。
- 插件目录、详情与原生视图进入实际 DockArea 或已有无项目窗口入口；安装授权、视图会话和任务不归布局管理。

当前工作台及控件覆盖见[组件逐项审查](GPUI_COMPONENT_AUDIT.md)；布局已存在不代表所有生命周期已验收。

## 下一步核对与完善

| 范围 | 当前计划与约束 |
| --- | --- |
| 面板导航 | 核对项目/节点/插件/助手目录、中心编辑器、Details、Results、Problems/Output/Logs 的打开与焦点；不恢复退出产品的项目库页面 |
| 资源拖入 | 使用原生拖放及目标分组；打开标签与画布坐标创建节点分别调用现有 owner，捕获身份拒绝迟到来源 |
| 通用菜单 | 布局动作复用根 DockArea，保存/关闭先经原协调者；固定标签若接入，所有关闭入口须遵守一致约束 |
| 尺寸和可见性 | 从实际布局与实体生命周期读取，不另建尺寸/可见性 authority；隐藏不代表关闭，不释放仍被持有的输入与结果 |
| 国际化与键盘 | 统一关闭、分屏、放大、溢出和焦点移动提示；文本输入焦点优先，不让全局动作误操作后台编辑器 |
| 恢复与项目切换 | 仅恢复可验证的资源和面板身份；失效引用明确失败，旧读取不重开关闭标签；重置不丢输入 |
| 原生窗口 | 设置、日志、结果的几何/焦点/关闭与业务租约分别管理；普通工作台浮动能力必须核实库 API 和当前 owner，不能从参考实现推断已接入 |

## 后续候选

以下保留原计划的产品意图，全部为评估候选；不是已实现声明，也不要求为布局库现有特性全量接入。
实施前核对 GPUI Kit 的真实公开能力，选择已有 owner，不承诺旧库 API 对应关系。

1. 覆盖式临时侧栏、固定标签、按任务分组与配色、窗口内浮动/整组移动；区分无标签自动隐藏与覆盖展开。
2. 命名布局预设、项目级布局记忆、布局导入/导出、布局撤销/重做；撤销不能复活已关闭租约或过期资源，
   与 Graph 文档历史使用独立入口，不建立可独立修改的第二拓扑。
3. 标签溢出/多行导航、分组工具栏、按面板类型约束尺寸、临时标签别名，以及确有产品需求时的顶部工具区。
   标签别名与资源重命名分开，后者仍走 Project 事务。
4. 同一图并排视图、多结果一键对比与等宽预设、同一结果多展示；先明确视图身份、独立暂态和共享文档/租约。
   当前移动标签不能直接宣称复制视图已实现。
5. 多个 Assistant 对话并排、固定多个检查对象、Project 与 Nodes 同时可见；会话与所检查资源保持明确绑定，
   不靠全局选择让所有视图被动切换。
6. 多日志领域并排，以及 Problems/Output/Logs 的诊断预设；三种业务流仍然独立，避免再建嵌套业务布局模型。
7. 可停靠架构/帮助查看、ADF 等报告汇总与详情并排、结果在工作台内放大；报告内容仍归 Results，布局只管理面板。
8. 长期插件任务和数据导入预览工作区；短选择/确认保持原生对话框，不为所有流程创建持久标签。
9. 受控界面意图按需求扩展为分屏、排列或预设选择；请求、去重与回执复用 Application，真正动作提交根 DockArea。
10. 多原生工作台窗口与跨窗口面板移动需独立评估实体、焦点、输入保护和租约交接；不引入浏览器弹出窗口方案。

优先顺序：先完成现有菜单、焦点、国际化、恢复与尺寸验收，再处理资源拖入/固定标签等日常操作，
最后按真实需要增加对比预设、多视图和多窗口。不能只打开库配置开关而跳过业务生命周期设计。
