# Features

- `application/` 编排跨领域用户用例，调用 services 并协调投影发布。
- `core/` 保存 Rust 投影、显式未保存草稿和共享交互状态。
- `domain/` 提供不依赖 React、Tauri 或 services 的领域规则。

节点 CSS 和尺寸归 `graph-editor/internal/ui/Nodes/nodeAppearance.ts`，资源图标颜色归
`project-explorer/internal/ui/activity/resourceIconColors.ts`；Domain 不持有这些呈现规则。

Core、Application 与共享呈现统一使用 `utils/frontendLogger` 生成日志记录；Application 的
Observability 模块在启动时连接现有日志传输并管理清理。公共 logger 不引用应用层或 IPC，
Core 不另建 console-only 实现。生命周期与信号归属见 [Observability](application/observability/README.md)。

Graph、Resource、Execution、Settings、Database 和界面读取能力复用 `core/state/readProjection.ts`。各 owner 必须不可变更新；提交投影在发布时通过 `freezePublishedValue` 冻结，读取端共享原始引用，不复制完整数据。React 使用统一 selector 订阅，未变化投影字段不触发消费者重渲染。`freezeProjectionSnapshot` 仅用于需要隔离外部输入的复制边界；不能重新放进高频读取 hook。Map/Set 同样遵守不可变替换约定，Readonly 类型禁止消费者调用修改方法。
只读投影的快照与通知由内部 Zustand store 管理，外部仍只获得 `getSnapshot / subscribe`；订阅遵循 Zustand 的生命周期，
发布时不再复制完整监听器数组。候选先进行顶层浅比较，实际变化时冻结并整体替换一次，保留原始分支引用。
内部 store 从空状态创建，再同步安装首次快照后才开放读取，避免 Zustand 的初始状态长期保留首份图或资源数据。
它只替换原有读取缓存的实现，不接受业务写入；源 owner 和现有订阅适配接口保持不变。
深冻结按自有可枚举字段遍历，避免为每个对象分配临时值数组。弱引用遍历缓存只记录需要递归的容器、非空数组和显式发布根，纯标量叶对象与嵌套空数组仍正常冻结，减少首次加载的缓存表分配。可复用的验证凭据只在完整冻结成功后对外可见；浅冻结不能作为深冻结凭据。

纯读取模块导出 selector hook 和使用中的命令式读取入口，不再并行维护重复的 `*ReadCapability` 包装对象。状态栏等调用方直接复用通用 `useReadProjection`，不另包工作台专用订阅 hook。

`core/execution` 用一次 Immer 发布图运行身份、终态、失败及逐输出活动和事件的结果版本。
等待摘要状态按当前摘要是否覆盖该后端版本派生；摘要安装不再回写 Execution 确认标记。
Results Application 继续拥有查询、缓存及租约；它按 Execution 提供的输出接纳范围准备失效，
由事件安装器在身份重验后统一写入运行事实。图运行展示只消费资源与执行 owner，
不再从结果查询缓存拼接另一份运行状态。已有命令提交、同步未知和清理入口继续各自表达其生命周期。
生命周期字段沿用同一 Immer 更新入口；重复 unknown 或清空不再发布无变化状态。
Execution 读取只比较每张图的状态、运行 ID 和经当前语义身份过滤的失败引用，用一次 Immer
更新新增、变化与删除的图记录。仅输出归属变化时保留读取快照，失败信息直接共享 owner 的不可变对象；
内部读取不再通过通用递归合并恢复引用。

图表已加载正文和本地草稿与名称、资源路径、修订及文档标记统一由 ResourceStore 拥有；
`core/chart` 保留窄读取投影和草稿编辑接口。载入、编辑、关闭及项目快照在一次 Immer 更新中发布正文与状态，
正文的结构共享由 `core/resource/resourceDocumentProjection` 按已验证的 Chart 字段及 encodings 浅比较，
复用原保存内容比较规则，只发生在写入边界；同值安装与无变化编辑保留引用且不标记 dirty。
保存的 IPC、项目及操作身份接纳归 Application，ResourceStore 仅在资源修订匹配时结算该回执：
未发生新编辑才安装权威正文，同时清除 stale/conflict 并按实际正文确定 dirty；较新的本地编辑继续保留。
项目重置同时清空正文和读取令牌，关闭后的迟到读取不能重新装回正文。数据库元数据更新使用
ResourceStore 的 `updateDatabaseMetadata`，完整快照由项目发布入口统一安装。
Chart Service 在 IPC 入口校验当前格式版本和正文，复用资源回执的共享 Chart 状态 guard；
列对响应校验有限坐标、轴格式、可空标签和显式请求点数上限，呈现层不重复解析。
初次视图读取与索引刷新都绑定捕获的发布版本；在途读取按项目、epoch、发布版本和路径共享，
新发布不会复用旧发布的请求。未缓存正文只为索引中存在的资源读取，返回时仍核对项目、资源修订和读取令牌。

`ResourceStore` 同时拥有资源索引、排序、发布修订、文档状态，以及 Mind/Doc 的带类型只读快照。
Mind/Doc 当前正文仍归 Rust Project，前端命令队列与未提交输入继续由 Application 拥有。
快照安装、重命名和释放在同一 Immer 中更新正文、文档标记与资源修订；共享比较只发生在安装边界，
同值快照及无变化删除不通知。Mind 按节点 ID 复用未变化节点及 reference，完整快照重排仍保留这些引用；
Doc 正文按字符串比较，两类快照的版本与头字段使用浅比较，不递归合并文件表。
读取令牌同时检查资源修订与存在性，
防止首次读取期间已从索引移除的文件被迟到响应重新装回。项目快照候选同时筛选文件正文，
保留外部缺失文件的 dirty 内容与未提交输入，显式删除及重命名移除旧路径，最终在原 Store 一次安装。
编辑器与 Mind Details 按文件类型和路径订阅同一快照，不再另设投影 Store。

`documentStateActions` 通过 ResourceStore 的文档写入方法
更新 loaded、dirty、stale 等状态及对应资源摘要，一次 Immer 更新只发布一次；读取投影只订阅这一 owner，
不会观察到文档与资源摘要不一致的中间状态。普通资源补丁只修改名称、路径、修订和存在性，不另行写入文档标记。
项目快照通过 `setSnapshot` 一次安装资源、文档标记、Graph 会话及实体/结果摘要、图表正文、Mind/Doc 快照和排序，项目加载、重置及恢复失败标记也在同一 Store 内发布。
同值快照、文档标记与恢复标记不重复通知；仅发布修订变化时保留资源、文档和排序的读取引用。
资源与文档记录按键进行浅比较，变化条目及删除在同一批次处理，未变记录和映射继续共享。
Graph 回执通过 ResourceStore 的 `installGraphSession` 同时安装图会话、实体、结果摘要、文档标记与资源修订，
共用原 dirty 状态规则；载入同步 missing 标记，图投影刷新同时清除 stale/conflict。
图保存的安装参数包含具体资源类型和 Rust 返回的资源修订；前端保存锁只更新该图会话，保留资源读取引用。
保存准入在发布锁之前捕获原会话身份，通知期间关闭或重开该图即停止旧保存，不认领或解锁后继。
单图安装在同步通知之后仍须保持本次准备的 sessionId/projectionGeneration 才报告成功；被重入替换的
图帧不继续旧结果对账。同帧启动后续保存只改变保存锁，仍确认前次安装，不由旧保存清除新锁。
单图回执和完整项目快照均不先发布图或资源的半份状态；图会话与资源状态的旧分离发布入口已删除。
文件回执的 dirty 判定继续考虑未提交的输入缓冲。

Graph 会话只保存前端实际读取的常量、编辑版本、投影和保存状态；完整 GraphDocument
仍由 Rust Project 拥有，并在 IPC 入口完整校验，前端不再将其节点参数、连接、端口绑定和输入状态
另存到 ResourceStore 或为保留引用遍历整棵文档。常量在会话安装边界按内容共享，未变常量
保持引用，不按相同 revision 或 semanticInputHash 跳过内容检查。常量编辑队列只读取该常量表，
新增节点识别复用已有图实体表的成员身份：Rust 投影 mapper 对 document 中的每个节点生成实体，
不另建 document 节点索引。完整相等快照仍不发布，候选失败不改当前会话；同步 delta 继续复用
现有 Immer 补丁入口及其未变化引用。同步基线只负责传输，不能代替可读取的会话 owner。

项目发布协调器接纳空回执或内容未变的权威索引时，通过 ResourceStore 的单字段入口推进发布修订；
连接候选和兼容节点目录因此继续获得版本失效信号，资源正文及文档读取引用保持不变。
恢复流程不能仅凭索引内容相同而跳过图投影准备；已加载的干净图继续走原会话准备与提交入口，
dirty 或保存中的图仍由现有保护规则保留。普通同版本索引刷新保留当前已知回执指纹，继续拒绝冲突回执；
版本前进或项目切换后，旧版本指纹不再用于判断新回执。

`ResourceStore.graphMeta` 按路径索引图类型与函数签名投影；项目加载、发布与清空在同一次更新中交付资源名称、修订及签名，不保留独立 GraphMetaStore。
图元数据候选统一由 `core/dataStore/graphMeta.ts` 的 `prepareGraphMetaSnapshot` 准备，首次加载与后续索引发布不再各自转换函数签名。
候选用一次 Immer 更新处理新增、修改和删除，直接更新签名参数和端口的具体字段。
递归类型只按当前 ValueType 的 Array、DataSeries 和 OneOf 分支更新；新增或类型变体变化时
隔离复制外部输入，未变图、端口类型及嵌套子分支保留引用，不再先递归合并、复制后再次合并。
内容接纳不单凭 functionRevision 跳过字段检查；处理只发生在准备边界，不进入 selector。
Graph 只读快照与函数详情直接读取该 owner。元数据属于项目索引，卸载已打开的图体时继续保留；
函数签名命令仍由 Application 捕获并重验项目及修订身份。
数据库索引转换归 `application/dataManagement/databaseRecords`，声明与修订在同一候选中更新，保留未变记录和映射；
数据库删除后的资源、数据记录和详情选择同样由项目发布入口对账，删除动作不在回执之后再次清理选择。
已加载数据库版本变化时，发布协调器按新索引的资源 revision 准备元数据，并与声明和资源版本在同一次更新中交付；未准备新元数据的版本变化仍在候选中清除旧缓存。未变版本继续复用原列、计数与加载状态。
首次加载的 schema 通过绑定索引 publication revision 的查询补充，不能回退到其他版本的旧行数。
当前已验证的 engine 仅为空 dataset 配置，首次安装隔离复制，之后共享原配置。
声明候选的增删和字段更新放在一次 Immer 中，不再递归合并整张表；列更新复用
`core/database/databaseProjection.updateDatabaseColumns`，只处理已验证的列和语义字段，
新增或变化的外部分支隔离复制，未变列及语义子分支保持引用。候选准备不发布 Store，
项目发布仍在现有提交边界重建候选并校验项目身份，避免覆盖准备期间发生的编辑。

数据库声明投影与资源名称、路径、revision 和项目发布版本由 ResourceStore 同一次更新交付，
项目加载、索引刷新、重命名、删除和清空共用这一 owner。独立 DatabaseStore 和数据库 revision 表已删除；
数据库修改命令与图表预览直接按资源键读取权威 revision。首次加载和后续发布共用数据库声明候选，
声明成员、名称和配置来自项目索引，运行时元数据仅补充列与行数。`core/database/read` 只提供窄读取订阅，
不再维护第二份 revision 投影。数据库分页与交互暂态仍归所属编辑器，不进入资源 Store。
元数据安装要求传入预期资源 revision，ResourceStore 核对资源存在性与版本后只更新列、行数、列数及已提供的数据修订号，
不接受声明身份或名称；相同内容不通知，未变列和其他数据库继续共享。
此入口与声明候选共用同一列更新函数，在原 ResourceStore 的一次 Immer 内更新列与计数。
导入在 `executeDatabaseCreate` 内核对创建 delta 与数据库身份，等待发布协调器后重验原项目身份，
核对索引与回执提供的资源路径，并使用该 delta 的 `toRevision` 安装元数据；前端不拼接资源路径。
管理界面不再在额外异步步骤之后无条件补写导入元数据，
该补全也不能独立新增声明。数据库已加载标记不代表文件编辑缓冲，权威索引删除数据库时同步移除
其投影与资源；缺失但仍加载的文件文档继续遵循原保留与冲突规则。

数据库元数据和分页读取由 `application/dataManagement/databaseRead` 组织，`databaseRecords` 只负责
数据转换与声明候选。一次读取捕获原项目身份、现有资源 revision 和调用方有效性，发出查询前及响应
接纳前共同核对；资源投影版本前进、资源移除、调用方取消或项目替换都会拒绝旧响应。读取依据不拥有
新计数器或版本表，继续查询 ResourceStore 的资源索引。
`readColumnSemanticDraft` 沿用同一读取依据，值域设置通过 `get_column_values` 获取完整去重值并与已有映射合并，保留已有标签、顺序及当前数据中未出现的已声明取值；只生成局部草稿，不写入资源投影。精确取值保持字符串，新增映射的标签默认等于原始值；值域编辑、顺序调整及数值约束统一由 Details 对话框确认，再走既有数据库修改入口。
数据库元数据在 `services/database/databaseWireParser` 使用模块级 Zod schema 校验一次；项目 schema
查询与单库读取、导入共用列结构，复用已有语义 guard。列名唯一、列数相符、计数为非负安全整数；
列的 `supportedSemanticTypes` 由后端依据 Physical 与写入兼容规则生成，wire 校验类型合法且不重复；投影保留该列表及未变引用，Details 直接使用，Physical 改变后随新元数据更新选项。
单库读取核对请求 ID，项目映射核对键与 ID，Application 再核对映射成员与同版索引一致。
数据库修改响应的 `data` 按元数据、编辑状态或 null 校验，回执复用原资源 wire parser。
索引、资源回执和元数据共用数据库引擎 guard。Application 只接收已验证的元数据，
不再跳过坏列、补声明默认值或通过类型断言修复未知响应；原宽松 `normalizeDatabaseRecord` 已删除。
分页在同一 wire 模块校验标量 cell、统一行宽、行 ID 唯一与数量对应，Service 核对响应未超过请求页长。
IPC 将 Rust `i64` 行 ID 编码为精确十进制字符串；前端校验其规范形式与范围，整条加载链原样保留，
表格直接使用该 ID，不再转为 number 或以页码补造身份。Application 在接纳有效版本的页面后，
核对行宽与已知元数据列数一致。数值单元格继续是有限浮点数，宽整数和日期等显示编码保持字符串。
列分布在 Services 按 numeric/string 变体校验列名唯一、字段与计数；SQLite、远程 SQL 和 Excel
发现响应共用字符串数组校验，保留后端名称的内容与顺序，不在 UI 中修复输入。
同一个捕获的 revision 作为必填 `expectedRevision` 传给元数据与分页 RPC；后端在查询前后校验 Project，
并确认 Runtime 读取基线的声明版本相符，防止前端尚未收到新发布时混入另一版本的数据。图表分布和列对
查询同样传递捕获的数据库 revision；缺少该版本时不查询。
数据面板的初始载入、翻页和数据刷新共用一条加载流程：一个请求序号贯穿元数据及分页，
等待元数据之后不重新取得请求所有权。首次载入与手动刷新先读取元数据；发布已准备元数据时直接读取分页，均按当前行数约束页码。
元数据查询返回 Dataset Store 的 `dataRevision`（无损十进制字符串），不是新的前端计数器。已接纳页面按原项目身份、资源存在性和该数据修订号判断是否仍可展示；进行中的查询仍严格校验资源 revision。卸载同时撤销请求并释放整页状态。
Semantic 修改只更新元数据；数据修订号不变时保留页面行数组、页码与选区，不显示加载状态或重新查询分页。Physical 转换、行数据或列成员变化推进数据修订号，重新读取第一页；手动刷新仍强制读取当前页。版本变化但缺少有效元数据时继续拒绝旧页，不序列化列 schema 猜测数据变化。
Chart 数据集选择器使用 Core 的 `selectDatabaseNames`，浅订阅 ID/名称。数据面板只浅订阅当前
数据库的列与计数，分页仍归同一个加载 hook；底栏的刷新复用该面板的当前页加载入口，导出复用
`useDatabaseExport`。工作台不再创建独立数据窗口或为数据刷新重新初始化项目。
`domain/databaseEditor/gridSelection` 统一选择类型、范围归属、增选/扩选及键盘锚点计算；
`useSelection` 仅持有组件局部状态，表格适配器保留 AG Grid 行/列身份、事件转换和绘制。
选区预览的行号、列名和文本通过既有工作台面板暂态一次提供给 Details；行号按当前页偏移计算，与表格一致。预览保留真实 `null`，与空字符串和文字 `null` 区分；未选择由缺少行号表示。只有预览组件订阅这些字段，列设置不跟随选区重置。
行选择同步使用真实行 ID 查询框架已有节点索引，分别批量取消和选中实际变化的行；只在行选择或页数据
变化时同步，单元格/列选择不扫描整页行。可见单元格与表头刷新继续交给 AG Grid，未构造第二份行节点索引。

统一提供，支持 Ctrl/Cmd 和大小写按键。剪贴板和高亮共用范围判断，仍按原主范围与 TSV 规则复制。
Data/Chart Details 共用 `useDatabaseMetadata` 管理版本订阅、读取及取消；即使旧请求尚未返回、列仍为空，

首次项目加载先读取索引，再按同一项目身份取得路径、按同一 publication revision 取得数据库 schema。
缓存复用仅限当前投影属于同一个项目。提交准备好的加载快照前，以及异步关闭旧项目面板后，重验原身份

文件行按自身图路径读取诊断数量，不生成或广播整项目诊断数量表。资源行接收独立选中布尔值及稳定动作，

`core/nodeCatalog/resourceCatalogIndex` 按已发布目录项数组的身份共享资源路径索引，弱引用缓存不延长旧目录生命周期。

每行只查询对应路径的候选；目录请求、语言、发布水位与失效仍由原 NodeCatalog Store/Application 拥有。

每次画布注册返回专属注销函数；卸载只移除原注册，即使同一面板的新注册复用同一个回调，旧清理也不影响它。
函数投放沿用拖动开始时的项目身份；面板激活完成后先重验身份，再读取当前注册的画布处理器。

项目选择页的新建/删除弹窗把输入、busy 和错误保留在本次打开的局部表单中，关闭时卸载；删除目标改变时重建表单。

系统目录选择和创建响应只在原表单仍挂载时更新呈现，不因关闭界面取消后台项目操作。

`useProjectPicker` 在每个页面挂载实例内统一准入一次操作，刷新、收藏、移除、打开、创建/删除、扫描、清理、
导入和定位文件都使用同一个局部操作句柄。忙碌呈现只由该句柄的开始/结束更新；重复请求返回本地
`project_picker_busy` 结果，不发出 IPC、覆盖在途页面错误或清除原忙碌状态。普通页面动作共用准入、错误和
结束逻辑，失败上下文继续携带原操作及目标，供页面重试；列表与右键菜单遵循相同忙碌状态。
初始列表读取与当前路径自动注册按序执行，自动注册在等待和响应后重验自身 effect 的有效性。
路径变化或卸载取消旧 effect 的后续呈现；文件选择前即持有操作句柄，页面关闭后的选择结果不再发出扫描/导入命令。
已提交的创建/删除回执仍由原生命周期 owner 校验和结算，页面句柄只限制局部列表、错误和导航的回写，
不代替 Rust 注册表、项目生命周期账本或全局进度 owner，也不建立跨窗口操作队列。

Settings 的唯一可写 owner 是 `settingsStore`。本地修改、重载、保存、重置和远端更新共用设置安装规则，
对两个仅含标量的设置分支使用 Zustand 的浅比较，保留未变化分支；相同值不重复发布。
本地存储读取是同步操作，重载一次发布完整设置及加载完成状态，不发布瞬时 loading 中间态。
待保存字段继续覆盖远端同名字段，远端更新不回声发布；持久化成功后才清除待保存补丁。
存储与跨窗口输入继续复用原有 `parseSettingsPatch`，没有增加解析契约或平行 Store。
主题消费者只订阅只读配色预设或亮暗模式；启动副作用只订阅配色、语言和平滑滚动。
菜单亮暗切换由 Application 动作在执行时读取当前配色及记忆预设，再通过原 `settingsUi` 更新；
菜单不为这一动作订阅整份外观设置。语言输入只更新设置，实际语言切换统一由 `SettingsEffectsProvider` 同步。
设置重置的确认、持久化及反馈由 `application/settings/useSettingsReset` 编排，界面只发出全部或分区重置意图。
UIHost 传入现有设置弹窗身份，重置确认通过 UIStore 的 `parentId` 归属于该弹窗，关闭父弹窗时按原规则取消子确认。
每个挂载页面从确认到保存只接纳一次重置；取消后可重试，确认后页面已经关闭则不再提交。
已调用的持久化继续由 Settings Store 完成，卸载只停止局部反馈回写，不增加共享操作 Store 或跨窗口锁。

Plugins 的共享注册表投影由 `application/plugins/pluginRegistry` 在每个 Workbench 挂载范围内拥有，
Rust Plugin Manager 仍是安装和启用状态的 authority。App 的 `PluginProvider` 只管理该实例生命周期，
Context 只传稳定读取与操作接口；列表按需浅订阅状态，插件页面按 ID 读取现有索引，不广播完整模型。
接受已验证的查询响应时按插件 ID 安装到现有注册表。同一 `packageDigest` 对应 Rust 校验并签名的
不可变包内容，直接复用 manifest；换包时按具体协议、预算、标量列表及贡献行浅比较，保留未变子分支。
运行状态、启用状态、安装代际、签名身份和有效授权预算仍接纳当前响应；列表、只读索引及查询状态
一次发布，同值响应不通知。比较只在查询安装边界执行，继续复用发布冻结入口。
安装、卸载及贡献布局协调归 Application，Workbench 继续拥有唯一布局 authority。
查询响应、排队打开和异步动作绑定原挂载身份；选择文件、包检查及确认后的未提交安装必须重验该身份，
卸载确认还核对当前安装代际。成功卸载先移除该代际的本地投影，再查询注册表，查询失败不复活已卸载项。
后端已提交的操作不因前端离开而回滚；新的挂载重新读取 Rust 注册表。语言变化只重译当前错误，不重新创建注册表 owner。

插件维护的历史页、游标、用量、诊断及操作状态归当前弹窗的 React state/ref。
弹窗仅在选中的插件及安装代际仍存在时挂载；同一安装身份的条目引用变化不清空分页或重发查询。
初次读取、刷新、翻页和清理共用同步准入，清理后的重新读取仍属于同一个操作，不能被第二次清理插入。
历史/游标/用量/诊断一次安装，重开或安装身份变化从新快照开始，旧响应不能覆盖新页面或清除新操作的 busy。
关闭页面不会取消已经提交的后端清理，但停止其后续读取和局部回写。原 `PluginViewSession` 继续串行交接视图 lease，
保留失败释放的身份；项目切换订阅只对 project scope 页面启用，插件宿主动作仍由 Service 的已验证回复类型决定。

节点目录 Store 每个项目、语言只持有最后一次接受的响应。成功刷新在一次 Immer 更新中安装响应、
请求状态和资源水位，并删除该请求已替代的旧响应；响应身份仍包含 Registry 指纹和资源发布版本。
资源水位及相关请求失效也在一次 Immer 更新中发布，没有请求变化时保留请求表引用。
刷新失败或正在刷新时保留最后可读响应，其他语言和项目不受替换影响。已持有的旧快照不被修改，
搜索索引继续按响应对象用 WeakMap 缓存；Store 不充当历史版本归档，项目重置仍清空原有 owner。
完整创建目录使用已有索引检索技术词、资源名和拼音，文本规范化复用 Domain 的 `normalizeCatalogSearchText`。
节点文档由 Details 读取本地化目录中的对应条目并展示。
普通目录停用、兼容目录停用或缺少图/起始端口时，对应项目、请求及图版本 selector 返回稳定空值；
恢复启用时读取当前 owner。兼容目录的起始端口身份复用 `portAddressKey`，不另用 JSON 序列化编码。

命令面板和工作台菜单通过 `useEditorHistoryAvailability` 按活动图订阅撤销、重做及保存中的标量投影，
使用 `useShallow` 复用未变化的组合结果。节点正文、坐标或结果更新不因替换会话对象而触发该订阅；
活动图仍来自工作台原生选择，保存期间继续屏蔽撤销与重做。

项目事件由 Service 的 `projectEventParser` 校验，`projectEventStream` 交付事件或失败条目；
Application 直接消费这些类型，不重新声明同一事件协议。`projectEventConsumer` 调用项目用例，
`projectEventIngress` 独占有界 FIFO、恢复和排空。恢复先丢弃增量尾部，再等待当前事件结束后请求
权威快照；消费者只请求恢复，不反向等待恢复任务。溢出、传输失败和消费者恢复请求共享在途恢复。
关闭立即拒绝新事件并清空等待队列，先等待消费者结束，再等待它可能新建的恢复任务，完成后才交付排空。
挂载引用与原始监听器生命周期继续由 `useProjectSync` 管理，不另建项目状态或订阅入口。
项目开始、取消及快照提交交回各自创建的生命周期身份；同步 Store 监听器若启动后继，旧步骤立即停止，
不继续清理后继侧栏、发布旧资源或借用后来捕获的 epoch。生命周期回执使用提交交回的身份完成结算。
项目加载先登记当前身份的在途任务，再发布 Loading；同步通知启动的后继保留自己的去重句柄，
旧任务只能清理自身，后继的重复加载共用同一请求和结算结果。
普通资源发布同样在资源版本、面板和目录通知后重验身份；旧回执在通知完成前仍留在原待结算队列，
由生命周期重置拒绝，不能把后继的同版本回执清除或把旧发布确认为成功。
Results 的项目失效重置由同一回执 owner 在成功结算时执行，直接回复与事件交付共用一次；
重复、失效以及仅注册表变化的回执不清空当前 Results，重置触发后继时也不再确认旧结算。

Details 总入口按当前目标读取资源名称、函数输入/输出、数据库记录、图表正文或选中日志。
节点消失时先按原资源身份回退到所属图详情，再读取对应字段；未选中某类详情时，其 selector 返回稳定空值。
函数名称和签名仍由 `buildFunctionResourceView` 单点组装，入口不物化完整 Event/Function/Database 目录。
Chart 的数据集选择器浅订阅各数据库的 ID 和名称，列及元数据已加载状态只读取当前数据库；
编码选项只随该列投影引用变化重建，空 schema 与尚未读取的 schema 继续区分。

节点 Details 按当前节点、端口和诊断显示文本选择投影，引用数组使用浅比较；参数编辑器消费只读协议值，不在 selector 或渲染中深拷贝。连接候选在打开选择器时查询 Rust，前端只映射候选标签、标出替换行为并保留当前已连接项用于显示；重复连接由 Rust 判定，Details 不另设候选排除规则。编辑草稿在用户修改或提交边界产生新值。
节点参数统一消费 Rust 的 `parameterGroups`，组内参数通过 `editor.kind` 选择控件，普通参数和依赖 Schema 的参数共用这一结构。Details 保留组顺序与说明，每个参数独立展开；画布从各组读取 `inlineAndDetail` 字段，折叠状态属于局部 UI。`setNodeParameters` 只提交用户修改的字段，null 表示清除显式值，合并、默认值、条件显隐和原子校验由 Rust 拥有。
数值参数编辑遵循当前 `Scalar/Numeric` 语义，允许小数；客户端保留必填、有限值和安全整数检查，不保留旧物理整数类型对应的“必须为整数”错误分支。

连接提示由 `application/graphEditing/useConnectionCandidates` 查询 Rust 的连接决策投影，普通连接和迁移共用实际 mutation planner。前端按后端的 append、replace、invalid 结果显示高亮、替换范围和候选列表，不推导类型兼容性或迁移容量。查询只保留当前起点及操作的一份结果，按项目、图编辑版本、语义身份和资源目录发布版本失效；迟到响应不能覆盖新手势，鼠标移动不触发 IPC。Pin 创建目录同样在这些身份变化时重新查询 Rust 的兼容目录；单纯结果状态更新不会重新查询。
候选查询仅在启用且存在起始端口时消费这些失效信号。空闲画布的相关 selector 返回稳定空值，
项目、图版本和资源目录更新不会通过候选查询唤醒它；开始手势时立即读取当前 owner 的值，
继续按完整身份查询并拒绝迟到结果。

端口与图输出的前端身份编码统一由 `shared/types/domain/portAddressKey.ts` 拥有，Domain
公开入口、投影校验、实体索引、连接候选和 Results 查询均复用该实现。端口键包含地址变体和各段
长度，图输出键再包含图路径；共享层只计算键，不保存状态或引入 Services 依赖。

`core/dataStore/graphProjection.ts` 准备只读图候选，ResourceStore 统一发布图会话、实体和结果有效性摘要及资源标记。打开、编辑、撤销、保存以及项目快照都先验证完整回执，再一次安装 `sessions / graphEntities / resultStates`；原图编辑 Store 已移除。完整快照和增量响应都按实体 ID 复用未变化的内容，发布时冻结对象。编辑版本和结果摘要版本独立接纳，迟到的较旧结果不能覆盖新运行状态。结果查询和持有租约仍由 Results Application 管理。
结果摘要在 `core/dataStore/graphResultProjection` 按图输出身份和连接两端身份共享有限字段记录，
完整图回执和独立结果查询共用这一入口。行重排保留未变记录及端点，数组顺序仍来自 Rust；
executionSessionId、semanticInputHash 和 revision 继续参与根状态比较及原接纳检查。
Results 的当前 Pin 和搜索读取同时依据图结果摘要与查询缓存，图帧改变时立即隐藏已失效绑定；
按结果引用读取的报告仍保留原租约与数据。可见绑定的只读投影复用统一订阅能力及未变引用，
输出索引只随不可变摘要分支变化重建，接纳、读取和对账共用同一有效性规则。
常量 Details 直接消费同一文档投影；每行按自身的类型、序列化值和表格内容引用转换编辑值，
不随其他常量修改而重新转换整张常量表。未变化的值继续传给已打开的 JSON 编辑器，名称修改也不重置值草稿。
转换仅存在于该行生命周期，未提交草稿仍为弹窗局部状态；提交按既有 Graph 队列合并到最新 Rust 回执。
常量字段与 JSON 文本在 `domain/graphConstants/valueInput` 的输入入口转换，复用共享 DataValue 规则，
向界面返回稳定错误码；非法值保留在局部草稿中，不调用提交动作。表格文本在确认时用模块级 Zod schema
检查有限标量单元格，再检查列长度和单列约束，禁止把溢出数值经 JSON 重新序列化成空值。
`constantValuePresentation` 只负责摘要、编辑文本和可编辑种类，组件只持有草稿、显示错误和转交合法值。
Rust 仍拥有常量提交、类型及最终文档校验。

Graph 剪贴板的 `lastKnown.valueType` 与文档、字面量共用 `isTypeExprWire`，
按同一 Rust TypeExpr 契约接纳包含 Class 的嵌套类型；导出回复和剪贴板读取不维护另一份类型解析。

单图安装和多图快照共用 `prepareGraphSessions`，显式传入已有图状态：先准备每张图的会话、实体桶与结果条目，再一次冻结完整批次。三个项目级表各自最多复制一次，删除过滤已经生成的新表直接参与候选构建；拒绝旧版本或内容未变化时保留原引用，完全无变化的批次返回原状态。中途校验失败或路径重复不会发布部分结果，项目快照仍在原提交边界一次安装。
实体安装直接更新现有 `GraphEntityBucket`，不再构造另一份临时规范化模型。首次加载在发布前填充新表；后续安装用一次 Immer `produce` 更新变化分支，按前后只读投影的引用跳过未变化节点及其端口。节点顺序和成员关系变化时仍按 ID 复用实体；仅移动节点不重建端口表、连线表或邻接表。连线变化只重建受影响端口的邻接数组，并按投影顺序扫描连线以保留重排语义；删除节点、端口和连线时同步清理索引。`blockedConnectionIds` 只随规范诊断变化重算，连线订阅按 ID 查询，不再逐条扫描诊断。
节点位置、显示、能力、端口添加项及诊断直接借用接收边界已共享的投影分支；Pin 的子字段同样来自
按端口身份共享后的投影，派生记录只比较本层字段，不再次递归共享整条端口。参数组在同一接收边界按
组键和参数键保留重排中的成员引用，实体桶直接借用已共享的参数组，不再重复递归。参数显示、编辑版本
及阻断连线标量索引只比较本层字段；连线端点已按端口键
共享后，连线记录同样使用浅比较。完整协议输入及递归参数值的安装边界仍保留内容与身份检查。
完整快照在一次 Immer `produce` 中共享图根、节点、端口、参数组和参数的固定拓扑，节点按 nodeId、
端口按完整地址、参数组和参数按 key 匹配。位置、显示、能力和端口连接能力等标量结构只做浅比较，
不再递归比较整个根或节点，也不通过第二次节点比较修复端口重排。只读输入负责比较，draft 只接收
固定字段或数组位置赋值；旧快照的次序不变，不添加另一份索引。全等优先保留旧根，已经共享的增量
无需替换子引用时保留输入节点、数组和根的身份。重复 ID、跨图及端点检查仍在完整候选上执行。
参数跨组搬迁沿用原有组内匹配范围，不保证复用来自另一组的旧参数引用。
参数值、literalOverride 和 protocolDefault 中的任意 JSON 在 draft 外共享，不把 JSON 键作为 draft
路径。连线端点、诊断位置与相关位置、端口添加项、Schema 字段，以及 basis 和类型状态的固定外壳
也在同一事务内共享；连线、诊断和 Schema 数组沿用位置匹配，保持输入次序。诊断参数与资源版本的
字符串字典仅浅比较整张表，不向 draft 的动态键写入。basis 的资源观察字典只比较条目的 kind/version，
在 draft 外用普通对象浅拷贝复用未变条目，保留自有 `__proto__` 等合法键。参数编辑器按 select、projectColumns 和 filterPredicate 的固定字段
共享选项、列约束及谓词，简单编辑器只做浅比较；切换变体或删除谓词字面量直接保留输入形状。
`core/dataStore/valueTypeProjection.ts` 由投影和常量共同使用，只按 ValueType 的 Array、DataSeries 和
OneOf 分支恢复旧引用，其余变体比较固定标量字段；类型状态的 dataType/domain 也走该入口，
全部在各自原有的一次 Immer 事务内完成。它以已校验输入为基础保留增量身份；图元数据仍使用
原来的旧值 draft 更新器，在新增或变体变化时隔离外部输入，不为复用遍历而增加完整克隆或嵌套事务。
参数值、端口字面量和序列化常量中的任意 JSON 值只在接收边界共享，组件仍读取现有投影。
常量中的序列化 Object 和表格列名沿用原数据契约，自有 `__proto__` 等合法 JSON 键不能被
当作原型操作、忽略或拒绝。常量读取镜像在既有安装入口通过一次 Immer `produce` 共享 UUID 表和
固定 DTO 字段外壳及上述 ValueType；表格列只按位置比较标量单元格并浅拷贝变化的列名表，序列化值仍在 draft 外递归共享，再写入固定字段，
任意 JSON 键不成为 draft 赋值路径。未变分支、同版本回复、字段删除、数组变化和已共享增量的输入身份均保留。
任意 JSON 分支仍使用现有递归共享。测试中的一次 Immer 参考在进入 draft 前识别含自有 `__proto__`
的字典子树，仅该子树复用现有 helper；合法动态键样例的行为与[测量记录](../../docs/benchmark/README.md)
用于比较整个常量入口，该费用差不能单独归因于 dataValue。后续直接对照保持同一 typed 外壳和一次
`produce`，仅临时替换 dataValue 遍历；500 条合法动态键常量的同值与嵌套变化各在 A/B/B/A 四进程中测量，
现有共享为 4.3–4.6 ms，候选为 29.6–30.3 ms，每组 30 样本。结合保留键、删除与增量身份验证，
此最小常量边界保留现有 draft 外共享；参考未进入生产。该样本并非所有 JSON 的穷举或纯 Immer 替代，
该常量对照不外推其他投影字段。
参数 `value`、输入 `literalOverride` 和 `protocolDefault` 另以普通 JSON 样本在原投影的一次
`produce` 内直接比较：500 节点各有三个独立值，计时外分别检查内容、旧值隔离、特殊键与引用身份。
同一 `prepareGraphSessions` 入口的 A/B/B/A 对照中，现有实现的完整快照准备为 25.8–34.2 ms，
仅替换三处 JSON 遍历的候选为 257.9–267.1 ms；各组 30 样本。三处作为同一投影 JSON 边界保留
现有 draft 外共享。共享增量两策略均低于 1 ms，但离散与跨进程漂移不支持速度差结论。
该依据只比较所测候选和合成规模的整体准备费用，不单独归因某字段、递归函数或特殊键回退；
不推广为其他模块、未来任意调用或所有 Immer 方案的例外。完整方法、源码 hash 与局限见上述测量记录。
`primaryPortDiagnostics` 是同一实体桶内按端口 ID 查询的扁平稀疏索引，仅在对应节点的
诊断引用变化时替换其条目。一次遍历选出每个端口的首个阻断诊断，无阻断时保留首个诊断，
并共享原始诊断对象；不额外分配每个节点的索引表。节点或诊断移除时在同一次发布中清理，位置和
无关字段变化复用原索引。Pin selector 直接按 ID 读取，不重复扫描列表、构造地址键或过滤数组；
完整问题列表及诊断语义仍来自 Rust 投影。
同步入口先冻结属于该响应的候选数据，再由现有 parser/guard 完成校验，成功后才更新基线并交付 Store。已成功校验且由 `deepReadonly` 完成深冻结的对象，可通过弱引用缓存复用节点结构、文档、结果摘要和节点局部语义检查；可变对象及仅浅冻结的输入不进入缓存。节点语义检查复用 shape guard 已验证的参数元数据与键唯一性，避免首次加载重复分配参数校验集合；直接传入的未验证节点仍执行这些检查。缓存不持有独立会话或延长对象生命周期，变化分支仍重新校验。每个变化的投影都检查图路径、重复 ID、端点存在性与方向及阻断诊断；同一不可变投影在同步和安装之间复用完整校验结果，结果语义哈希、会话及响应绑定继续在接纳前核对。`shareProjection` 保留已经完成结构共享的增量对象身份，只在需要替换子引用时分配容器；完整快照继续复用与旧投影相等的分支。
`pnpm bench:graph` 对完整快照和增量分别报告同步解析、实体安装及两者合计的耗时；安装样本在计时外准备已验证的输入，首次快照样本每次清空基线和该图 Store，增量样本先建立基线。已有图另测同值、单节点移动及节点/端口重排的完整快照；每个样本恢复相同已安装基线，再接收全新输入，使用每节点两个端口来实际覆盖端口重排。setup 检查完整行为，每个样本在计时外核对冻结和预期引用。样本之间清理 mock 调用历史，避免历史响应干扰对象回收。可用 `--testNamePattern='5000 nodes: snapshot'`、`--testNamePattern='5000 nodes: delta'` 或 `--testNamePattern='^5000 nodes: existing graph'` 独立测量。该基准使用模拟 IPC，不测量 Rust 处理、真实传输或浏览器布局与绘制，桌面交互仍需人工验收。

节点视图按输入、输出分组并共享原始 Pin 引用；连接数量直接读取 Rust 的 `connections.current`，不再派生第二套 Pin 连接状态。连线记录保留必需的结构化端点和顺序字段，查看结果与诊断直接消费这些字段。

`useNodeView` 用一个 Zustand selector 读取节点正文，缓存归当前图路径和节点 ID 的订阅所有。
节点与端口表引用未变时直接复用视图；端口表变化时只遍历该节点的端口 ID，一次核对引用及分组顺序，

句柄只标识操作身份；替换可见进度不取消旧业务任务，也不在新任务结束后恢复旧进度。

由该 owner 统一将提交快照的变化同步到已有实时 entry，不依赖面板是否订阅；读取订阅只监听本 scope。
