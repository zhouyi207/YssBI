# GPUI desktop host

> Status: Current
> Scope: GPUI 原生桌面入口、项目导航、工作台、资源及图表编辑、执行结果、Assistant、模型设置与插件管理
> Canonical owners: Cargo.toml、src/main.rs、src/window_chrome.rs、src/services.rs、src/projects/、src/workbench/、src/canvas/、src/documents/、src/minds/、src/databases/、src/charts/、src/plots/、src/imports/、src/plugins/、src/settings/、src/assistant/、src/file_commands.rs
> Update when: 原生宿主能力、状态所有权、启动方式或验收范围变化时

这是 workspace 的默认原生桌面入口，使用 GPUI Pre 0.3.8 和 GPUI Component 0.7.1。
窗口及画布由 GPU 原生绘制，不启用组件库的 WebView feature。
窗口手势由项目的 `window_chrome` 统一处理，组件依赖直接使用 crates.io 发布版。

基础界面优先复用 `gpui-component`：标题区域使用原窗口图标与主题，菜单使用 `AppMenuBar`，工作台使用 `DockSkin` 与根 `DockArea`，
数据库及结果使用 `Table`，设置导航使用 `Sidebar` / `SidebarMenu`，输入、菜单、按钮、
Markdown 与常规表单使用对应原生控件。主题由 `appearance` 统一设置，不另建基础组件或布局模型。
图、Mind 画布与专用预览保留本模块的绘制和交互；业务状态、校验及异步提交仍归现有 owner。
图、数据库、图表的删除，以及供应商删除和放弃设置，使用 `AlertDialog` 确认，危险操作有明确的危险按钮；
普通编辑表单继续使用 `Dialog`。其他系统确认提示尚未全部替换。

```sh
cargo run
cargo run -- /absolute/path/to/project
cargo run -- /absolute/path/to/project events/example.yssbi-event
cargo run -- /absolute/path/to/project docs/example.md
cargo run -- /absolute/path/to/project minds/example.yssbi-mind
cargo run -- /absolute/path/to/project <database-id>
cargo run -- /absolute/path/to/project charts/example.yssbi-chart
cargo build --release
```

根 Cargo profile 对开发构建的宿主及 GPUI、Naga 着色器编译器、路径细分和布局依赖做定向优化，保留调试信息；
普通 `cargo run` 会直接应用这些配置。WGPU 每次新建窗口都会同步编译着色器，Naga 的定向优化
减少设置等独立窗口打开时的主线程停顿。首次构建受影响依赖会更慢，业务 crate 仍沿用默认开发配置。
帧率验收使用 `cargo run --release`：120Hz 每帧预算约 8.3ms，需在相同图
规模、窗口尺寸和显示器刷新率下实测平移、缩放、节点拖动与连接，不能从 GPU 架构直接推断达标。

五个示例的 catalog 和 Parquet 随源码提供，开发运行不需要下载来源。独立运行或分发时，
从根目录执行下列命令，将生成的 `resources` 目录与对应可执行文件一起保留：

```sh
cargo run -p yss-application --example build_samples -- --check --stage target/debug/resources/samples
# release 构建使用 target/release/resources/samples
```

来源、归属和维护时的输入下载见[示例资产](../../resources/samples/README.md)。此入口只准备资源；
各平台安装包和签名仍待迁移。

未提供目录时显示简洁欢迎页；Ctrl/Cmd+O 直接打开项目目录，Ctrl+Alt+O / Cmd+Option+O 搜索最近项目。
第二个参数可指定图、文档、Mind 相对路径或项目索引中的数据库 ID。
未指定资源时恢复已保存标签，否则优先打开首个 Event 图，再选择首个 Function 图。
项目和图由现有 Application 用例打开，启动读取发生在窗口事件循环之前，后续阻塞操作在
Tokio blocking pool 执行，指针事件不读取磁盘。

## 模块、状态与数据流

- `projects/form`：新建与另存为的未提交名称和目录输入；默认位置由原 registry owner 查询。
  提交复用原生命周期用例，部分写入失败保留已写入目标和恢复入口，不重复创建。
- `projects/recent`：原 ProjectManagement 登记记录的只读投影，只展示有 last_opened_at 的记录，排序沿用 Rust owner；
  后台读取合并刷新需求，失败保留目录打开入口，捕获的读取代次和完整记录拒绝过期选择。
  `recent/picker` 使用组件 ListState/List 的输入、虚拟列表、焦点及键盘选择，搜索只匹配名称和原路径；
  搜索与列表更新重置选择，弹窗关闭释放输入和列表实体，不把视图记录写成另一份最近项目文件。
- `workbench/projects`：目录选择、最近项目弹窗、保存确认和类型化项目命令；新建、打开、另存为、关闭均调用原 Application。
  操作后查询实际激活与索引，成功切换才替换编辑器；同一项目仍保留输入。项目路径精确使用 Rust 返回的入口文件路径。
  宿主 lifecycle 拒绝迟到目录选择、确认和安装，替换期间停止旧交付，保存回执接纳后才继续后续命令。
  关闭项目停止原 watcher 并回到欢迎页；窗口退出复用同一保存确认。近期记录读取不阻塞直接打开目录。
- `workbench/welcome`：空工作台的打开/新建入口及最近六项，一次点击打开捕获记录；只消费原登记投影与已有项目操作。
  欢迎页采用窄幅纵向分组与紧凑整行 ghost 按钮，快捷键提示读取工作台的实际 action binding；最近项目的名称与路径同排，悬停显示完整路径。
  独立项目库选择页与顶栏项目库按钮已移除；收藏、扫描、登记清理和回收站不再作为原生打开流程入口，底层登记服务仍保留。
- `documents`：原生 Markdown 编辑器、可选择的 GFM 预览及文本撤销/重做。输入是未提交 buffer，
  明确 Save 捕获当前 FileVersion，提交原 DocEdit 后调用原 Save；持久化失败保留中间编辑快照和输入。
  项目或版本失效不覆盖当前输入，干净文档可安装同一后端的后续投影；读取/保存期间收到的失效通知合并后重新查询。
  数学公式与外部引用预览仍待迁移。
- `minds`：Project MindSnapshot 的原生树画布。layout 按父子关系、兄弟顺序、折叠状态和内容推导坐标；
  render 绘制有界可见主题、Markdown 标签与合并曲线；input 拥有选择、框选、平移、缩放与取消。
  details 挂载到已有 Details 面板；buffers 只保留捕获版本的未提交主题文本，切换主题保留输入。
  commands 将当前输入与结构操作组成一次原 MindEdit 批次，显式 Save 才写文件；过期输入不自动覆盖后端。
  恢复内容只放弃当前主题未应用的文本，读取/保存期间的失效通知合并后重新查询。
  节点坐标不写入文件，节点和群组不可单独拖动。当前高度按内容估算，长 Markdown 的测量仍需完善。
- `file_commands`：Doc/Mind 共用的捕获版本、编辑和保存提交，仍分别调用原类型化 Application 入口。
  写入失败保留已提交编辑的快照，后续保存不会沿用旧版本。
- `charts`：当前 ChartDocument 的未提交配置与已保存内容，类型直接使用原 ChartType；Project 仍拥有文件和资源版本。
  query 在 worker 按项目 publication 读取图表，按数据库资源版本读取元数据、分布或有界列对；新配置取消旧交付，
  较旧目录投影不能覆盖较新读取。匹配来源的不可变元数据由 Details/预览共享，同一数据库版本下更换编码可直接复用；失效列或预览失败不丢弃配置。
  `query/preview` 在查询前核对编码列，区分缺列、数据源删除、无有限坐标与读取失败；视图显示本地化原因、稳定错误码及重试，不展示后端内部错误正文。
  重试刷新项目读取基线并保留脏草稿。首次打开接纳工作台与读取结果中更新的目录，再启动预览；文件版本已变化时才重读配置，删除后的旧交付不能恢复资源。
  commands 显式提交完整配置并沿用 GUI Save 的当前 Rust 基线；已接纳保存之后再排队刷新，保存全部和后续项目导航共享原流程。
  外部修改时保留脏草稿并提示覆盖语义；删除后的旧读取不能恢复已删除文件。Rename/Delete/Copy 仍校验原资源版本。
- `charts/details`：数据源与列菜单在打开时才从共享目录/元数据生成选项，数值轴直接消费后端 Semantic 类型；列清单按 50 项分页。
  再选当前数据源/图表类型保留编码；实际更换才重置。无变化草稿不安排读取，旧菜单仍由原草稿代次和项目 publication 校验。
- `plots`：独立图表与结果图形共用 GPUI Plot、轴、网格与缓存曲线，直接绘制后端点；直方图使用现有 BarChart 和原分布计数，
  分箱身份按原顺序区分相同显示标签。直方图仅请求所选列分布，由 Runtime 在聚合前投影；绘图范围及像素映射留在视图，不计算统计分布。
  date 使用天、datetime 使用微秒的原算术表示；刻度和悬浮信息保留原日历/钟面字段，不换为本地时区。
  `cartesian/marks` 复用组件 Line/Area 和 PathCaches；ECDF 从零值开始按 StepAfter 绘制，KDE 填充至零基线。
  默认范围包含参考线端点，显式 domain 保留升/降方向，固定概率轴为 [0, 1]；图形裁剪在坐标区内。
  气泡半径按大小平方根映射，零大小不绘制；悬浮显示原坐标和大小。主题来自现有 ActiveTheme。
  `frame` 复用组件轴、网格和文本测量；`matrix` 共用矩阵单元格/图例，相关系数使用 [-1,1]，热力颜色范围来自原矩阵，重复标签仍按行列位置区分。
  `correlogram` 显示原 ACF/PACF、零线与置信带；`distribution` 绘制后端四分位数/须线/异常点和缓存的小提琴轮廓，不估计密度。
  `interval` 共用误差线与系数区间，系数每页 100 行，范围一次准备，悬浮身份随页改变；`nomogram` 仅排序并布局后端刻度，支持滚动查看全部轴。
  `composite` 共用帕累托和组合图的柱/线，复用 Frame 的右轴与缓存曲线；帕累托每页 100 项，右轴固定 0–100%，翻页不重新计算累计比例。
  组合图共轴时范围包含两组值，双轴时折线独立定标；相同标签用位置区分，悬浮保留原词频整数和两组值。
  `wordcloud/layout` 用 GPUI 字体测量按原词序进行有界螺旋排布；数据身份、尺寸和字体不变时复用原排布，主题改变仅重新着色。
  词云保留中文/emoji 与原词频；长词缩小至可用宽度，文本只在展示时折叠空白，提示显示实际排下的词数、原唯一词数和总出现次数。
- `workbench/charts`：图表目录打开、UI intent、Details、标签恢复及脏窗口保护；弱引用表不拥有拓扑。
  图表新建复用原生命名入口，目录右键支持重命名、复制、删除和路径复制；实际目标来自原回执，目录仍重读 Project 索引。
- `imports`：来源选择、原生文件选择、CSV 配置、SQL 连接输入、工作表/表选择与示例目录。
  inputs 将暂态输入转换为现有 DatabaseImportSource；连接配置使用 URL 编码，密码和连接串默认遮蔽。
  返回同一连接表单保留端口；更换引擎时只有原默认端口跟随更新，自定义端口与其余输入继续保留，关闭检查按当前引擎判断脏输入。
  输入控件的 Enter 事件调用当前文件或连接步骤的原提交入口，忙碌期间不重复提交，表选择页仍需明确选择目标。
  discovery 在 worker 调用原 Excel/SQLite/SQL 查询和 SampleCatalog。`imports/selection` 统一渲染虚拟表/工作表列表，
  本地来源展示文件名并悬浮显示路径；远端只展示引擎与服务器地址，不将连接串凭据或查询参数带入提示框。
  `imports/samples` 直接消费原目录，复用本地化名称和说明，显示行列数、KB/MB 大小、空目录与当前导入项进度；
  行回调仅捕获示例 ID 与版本，不复制整项元数据。目录失败提供重试，导入失败保留目录与选择入口。
  `imports/feedback` 将原 SampleError 映射到本地化提示；数据库提交或会话刷新失败仍提示检查实际项目结果后再重试。
  三类来源共用暂态步骤状态，窄窗口下分类横向排列；未实现的 REST API 占位入口不注册原生操作。
  读取与导入期间锁定输入；失败保留原表单，取消时保护未提交的配置。仅确认后提交导入。
- `workbench/imports`：捕获项目与宿主 lifecycle，调用原类型化导入或示例导入入口并发布实际回执；
  读取权威项目索引后打开新数据库，不从回执拼接目录。提交结果不确定时重新读取目录，保留输入并提示检查。
- `databases`：仅持有 Application 元数据、编辑状态及每页 100 行的读取投影，复用原数据库历史与保存 owner。
  query 使用同一资源版本查询元数据、编辑状态与页面；语义变更保留数据修订号相同的已接纳页面，
  数据变化重新读取并将超出范围的页移到最后一页。grid 使用原生虚拟表格与稳定行 ID，精确整数直接显示。
  grid 与 Details 共享同一份不可变元数据，表头显示原列类型；行号是固定展示列，不进入数据列索引、复制或列设置。
  布尔值显示只读勾选，数字右对齐，空值使用弱化样式；视图不创建参考网格的补位数据列，短页空白补位行不读取真实行 ID。
  details 展示元数据与选中内容；`details/columns` 按 50 列分页提供默认收起的逐列设置，空表与未选表格单元格时同样可用。
  折叠状态按列名保留，元数据更新移除已消失列；只渲染当前页已展开的字段，不再截断前 100 列。
  设置目标来自明确展开的列，不由多选范围推断；菜单仅捕获列名与资源版本，点击时读取原元数据，不在渲染时复制完整语义映射。
  commands 在 worker 提交类型转换、语义、显式保存与 CSV/Parquet 导出。
  过期字段菜单和导出选择不能盲目使用新版本；原应用会话在保存后替换，工作台重新绑定事件与图执行投影。
  数据库设置在原 mutation 提交时已写入项目，EditState 的 dirty 表示运行时历史尚未 checkpoint；
  Save 建立检查点并结束该历史，不能将其解释为文本 buffer 的未写入更改。关闭提示明确直接退出会保留已应用的设置。
- `databases/selection`：组件 TableState 继续拥有活动光标、焦点、滚动和键盘导航；视图只增加范围锚点、
  拖动状态和有界高亮。拖选、Shift 点击/方向键及整行/整列扩选限定在当前页；Ctrl/Cmd 点击增选矩形或切换行/列，
  Ctrl/Cmd+Shift 点击增加范围。取消当前行/列时，将组件光标移到仍选中的索引，最后一项取消后清空；适配器拒绝把光标回调再解释为增选。
  键盘继续使用组件光标，展示行号列由适配器跳过；新页清除选区，匹配数据修订号的元数据刷新保留选择。
  `selection/ranges` 持有范围与索引集合，统计合并重叠范围；单矩形计数不扫描页面。复制多矩形中的当前范围，
  离散行列按页面顺序复制，空值成为空字段，TSV 保留制表符/换行/引号转义；未就绪时不复制。
  Details 从同一选区与组件光标派生主要单元格，复用默认收起的 Collapsible 与只读 Textarea 支持展开和长文本选择，区分未选择、NULL 与空字符串；
  表格选区只控制预览与复制；字段修改始终使用 Details 中明确展开的列。
- `databases/semantic`：对话框拥有未提交的 ColumnSemantic 草稿，按捕获版本读取完整非空去重取值；切换类别语义保留已声明但未出现的值、标签和顺序。
  读取失败可重试；过期草稿拒绝提交并保留输入。`semantic/inputs` 只创建当前 50 项的原生输入，翻页、增删与排序先接纳输入再释放旧控件，跨页移动跟随目标页。
  `semantic/fields` 展示可编辑存储值、标签、顺序、二元正值与精确数值约束；正值跟随值更名，删除对应项会清除，也可显式选择未指定。
  提交时检查重复值、二元数量和共享映射上限，存储类型兼容性、允许值域及数值精度仍由原 Application/Arrow 校验；失败不丢弃输入。
  未改变语义时直接关闭，不调用 mutation；成功仍交付原 EditState 与资源回执。物理转换确认期间阻止重复请求，取消后处理排队刷新。
- `databases/toolbar`：刷新、导出、复制和翻页使用组件图标按钮，窄面板自然换行；行号范围、页码和行列计数从已接纳页面派生。
  worker 的读取耗时随页面一起交付，元数据单独刷新不覆盖上次分页耗时；导出文件选择期间锁定重复操作，取消后继续处理已排队的刷新。
- `workbench/documents`、`workbench/minds` 与 `workbench/databases`：资源打开、索引驱动导航、UI intent、Details、标签恢复；
  面板只按资源弱引用查找，排序、选中及位置由原 DockArea 持有。
- `workbench/saving`：捕获实际脏图、文档、思维导图、图表、数据库与模型设置的保存请求，安装各自回执。输入冲突在执行前拒绝整批保存准备，
  并释放已准备的控件；实际文件保存分别提交，部分失败仍安装已成功或已编辑的原回执。
- `workbench/menus`：单一 GPUI Menu 定义提供文件、资源子菜单和视图导航，供 AppMenuBar 及系统菜单消费；
  仅缓存忙碌和项目可用性，变化时重新发布菜单，不持有布局状态。当前保存消费菜单恢复的编辑焦点；
  设置窗口的当前保存消费其原设置输入，其他工作台菜单命令转交主窗口。

- `workbench/settings`：顶栏、视图菜单、Ctrl/Cmd+, 和助手入口统一打开独立的原生设置窗口，

  当前迁移 AI 供应商、模型、默认模型及模型发现；保存、删除和默认模型回执发布原生目录失效通知，
  会话重新查询原模型服务。项目知识库已接入原来源服务；外观偏好仍待接入。
- `assistant`：每个明确 session 的原生会话面板、未提交输入、资源引用、运行选项与待发送队列。
  commands 调用原 Application 会话校验/模型选择和 HarnessHost 提交/取消；模型循环由原 owner 执行，
  点击发送清出的原文保留在待确认请求，失败时用持久 TurnStarted 重验是否已接纳，不自动重复发送。
  队列捕获入队时的模型和选项；手动发送下一条不更改会话后续选择。当前草稿仅在本次工作台缓存中保留。
- `assistant/stream`：先订阅原生交付再从持久序号 0 重放，在未发布候选中合并有界实时缓冲，

  项目会话变化重新验证原归属和绑定，历史不成为新的授权。接近底部时跟随流式正文，浏览早期内容时保持位置。
- `assistant/projection`：消费现有公开 AssistantEvent，形成消息、工具、任务、计划、引用和供应商报告的 Token 用量投影。

  render 初次呈现最近 20 轮，按批展开较早历史；Markdown、推理文本、任务和工具详情均由原生控件呈现。
- `assistant/inspect`：按需校验当前会话并读取 ledger 或控制工具事件，复用原 AssistantToolInspection；
  参数不复制原请求中的凭据、数据行、正文和内部版本。引用通过原知识服务校验来源后显示片段与资源定位。
- `workbench/assistant`：独立读取 Rust Assistant Activity 文档并交给共用 ActivityPanel，新建/重命名后重读原目录，
  不从操作回执拼接列表、不为目录订阅完整历史。会话缓存只按 ID 查找和保留暂态输入，不持有布局拓扑；
  同一会话重复打开选择原面板，关闭标签不取消运行，同一工作台内重开保留输入；项目替换释放旧缓存。
  项目内当前使用中心标签，无项目时在原生弹层呈现同一个根 DockArea；布局恢复校验持久 session 的项目归属。
  独立 AI 分组、缓存释放和跨重启草稿保存仍待完善，不能以当前基本界面代替这些生命周期验收。
- `main`：命令行参数、执行器、原生资源、窗口及快捷键；执行器存活到窗口循环结束。
- `window_chrome`：主工作台与独立设置窗口共用原生标题区域和手势。每个组件 Root 的插件持有一份暂态拖动标志，
  在实际左键按住时移交平台拖动，在区域内外释放、指针离开或无左键的移动时清理。
  根捕获阶段根据组件公开的 window_paddings、实际窗口尺寸及贴边状态，优先消费边缘缩放按下；

- `window_chrome/controls`：复用组件的窗口图标及主题颜色，根据平台装饰和原生能力呈现最小化、最大化/还原与关闭；

  蓝色用于焦点与主要操作。通过组件库 Theme::update 同步颜色、语义 token 和基础控件投影，不持有业务或布局状态。

  `information` 读取原观测/抽样数量、置信水平与预测时点；`render` 负责显示和局部翻页，范围在 worker 准备，词云像素排布在原生字体可用时缓存。
  普通折线的工具栏可展开并切换数据点；ROC 不显示点开关。切换不读取、重新解析或执行结果，语言/主题改变不重置开关。
  载荷无效显示图形格式错误；完整报告和独立图形窗口继续待迁移。
- `results/table` 与 `results/value`：虚拟表格、概览与按需展开字段；结构化报告的数组只展示后端数据引用，
  点击后按原 ResultTablePart 读取有界页。标量保留空值、布尔值与宽整数，前端不计算统计量。
  线性模型和报告的普通 JSON 元数据复用 Node Kernel 的运行值转换，字段树与表引用保留原结构。
- `workbench/logs`：直接订阅中立 LogRuntime 的已提交记录，recent buffer 有界、虚拟列表绘制；
  清空只清视图，缺口和慢消费恢复 recent snapshot，存储失败显示不可用。关闭释放原生订阅。
- `services/paths`：保持应用标识和各平台数据/日志目录约定；`YSSBI_APP_DATA_DIR` 可指定绝对路径，
  用于隔离迁移验收的项目注册、Harness、模型设置、插件状态和日志；示例优先使用可执行文件旁的 resources/samples。
- `text`：原生 UI 本地化；assets 中的中文资源取自现有桌面文案，图诊断直接读取 Rust 的原始模板定义，
  校验 code/message key 及所需参数后一次替换。未知模板或缺失参数显示通用提示，不展示原始模板键；
  Problems 按后端 severity 呈现图标和颜色，blocking 仍由后端独立决定。

依赖方向为原生宿主 → Application/共享投影与协议。Application/Project/Graph 不依赖 GPUI。
Project 是 GraphDocument、历史和保存身份的唯一 authority；没有原生图草稿、UI 历史或格式转换。
Activity 条目直接消费 Rust ActivityPanelDocument；搜索与分类展开留在视图，不从磁盘重建目录。
Details 参数输入是未提交暂态；应用参数时通过匹配版本的后端文档保留其他参数，再提交现有编辑事务。
